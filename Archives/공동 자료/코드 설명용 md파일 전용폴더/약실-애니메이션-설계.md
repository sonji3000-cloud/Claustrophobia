# 약실 개폐 애니메이션 설계

2026-11-13 · `AnimationIK` · 구현 전 초안

## 목표

포수석에서 약실을 바라보고 `Space`로 조작하면 폐쇄기가 열린 자세와 닫힌 자세 사이를 부드럽게 회전한다. 기존 `TankInterior` 씬의 `BreechOpen`, `BreechClosed`는 위치가 같고 회전만 다르므로, 현재 모델과 회전축을 그대로 써서 제자리 개폐를 구현한다.

지금은 `TankBreech`가 `TankGun.StateChanged`를 받을 때 `breech_block`을 해당 자세로 즉시 옮긴다. 이 부분에 시간 보간을 추가하면 현재 상태 흐름을 이용해 개폐 움직임을 만들 수 있다. [TankBreech.cs](../../../source/Claustrophobia/Assets/TankPrototype/Scripts/TankBreech.cs) · [TankInterior.unity](../../../source/Claustrophobia/Assets/TankPrototype/Scenes/TankInterior.unity)

## 상태와 움직임

| `TankGun` 상태 | 폐쇄기 목표 자세 |
| --- | --- |
| `EmptyOpen`, `LoadedOpen` | `BreechOpen` |
| `EmptyClosed`, `Ready`, `Recovering` | `BreechClosed` |

- 빈 약실 열기·닫기와 장전된 약실 열기·닫기에서만 개폐가 시작된다. 열린 채로 탄을 삽입하거나 닫힌 채로 발사 후 복구할 때는 목표 자세가 같으므로 동작을 다시 시작하지 않는다.
- 처음 바인딩하거나 컴포넌트를 다시 켤 때는 현재 `TankGun.State`에 해당하는 자세를 바로 적용한다. 진행 중에 개폐 방향이 바뀌면 그 순간의 위치에서 반대로 움직인다.
- 발사 후에는 기존 상태 흐름대로 약실이 닫힌 상태를 유지한다. `Recovering`이 끝나면 `EmptyClosed`로 전환되고, 다음 열기 조작에서 다시 움직인다. [TankGun.cs](../../../source/Claustrophobia/Assets/TankPrototype/Scripts/TankGun.cs)

## 구현 방법

1. `TankBreech`의 `block`, `openPose`, `closedPose`와 씬의 직렬화 참조를 사용한다. 개폐 시간은 Inspector에서 조정할 수 있게 하고, 전체 이동의 시작값은 **0.35초**로 제안한다. 0초는 현재처럼 즉시 적용하는 설정으로 둔다.
2. `OnStateChanged`에서 상태를 열림 또는 닫힘 목표로 바꾼다. 현재 진행도는 닫힘 `0`, 열림 `1` 사이의 값으로 관리한다. 진행도는 애니메이션에만 사용하고 장전 가능 여부는 `TankGun`의 상태에서 읽는다.
3. 개폐 중에만 `Update`에서 `Time.deltaTime`으로 진행도를 목표까지 이동시킨다. `Mathf.SmoothStep`으로 시작과 끝의 움직임을 완만하게 만들고, 두 포즈의 위치와 회전을 각각 `Vector3.Lerp`와 `Quaternion.Slerp`로 보간해 `block`에 적용한다. 끝에 도달하면 포즈 갱신을 멈춘다.
4. `Attach`에서 기존 이벤트 구독과 함께 현재 포즈를 초기화한다. `Detach`와 비활성화에서 진행을 멈춘다. 포즈가 하나만 연결된 구성이 있으면 해당 목표 포즈를 적용할 수 있을 때 즉시 적용하는 기존 동작을 유지한다.

개폐 중에는 캐시된 참조와 값 타입 계산을 사용한다. 에셋에서 고정한 계층과 포즈를 사용하므로 실행 중에 오브젝트를 만들거나 본을 검색할 필요가 없다.

## 장전과 멀티플레이

첫 구현은 폐쇄기의 시각적 움직임을 다룬다. 포탄 삽입, 표시와 소비, 발사 승인, 발사 후 복구는 기존 `TankGun`과 `TankBreech` 경로를 사용한다. 따라서 빠르게 연속 조작하면 화면에서 폐쇄기가 아직 움직이는 중에 장전 또는 발사가 승인될 수 있다. 개폐가 실제 조작 시간으로 작동해야 한다면 Host가 완료 시점을 관리하는 설계를 별도로 적용해야 한다.

멀티플레이에서는 Host가 확정하고 복제한 약실 상태를 각 클라이언트가 받아 개폐를 재생한다. 애니메이션 진행도를 따로 복제할 필요는 없다. 상태를 받은 시점에 움직임을 시작하므로 화면상의 개폐 시작 프레임은 클라이언트마다 다를 수 있다. [약실 상태와 네트워크 승인](../../../source/Claustrophobia/Docs/Tank-Weapon-Network-Sync.md#3-약실-상태와-host의-발사-승인)

## 구현 후 확인

| 확인 항목 | 기대 결과 |
| --- | --- |
| `TankTest` Play → `F9` → 포수석에서 빈 약실을 `Space`로 열고 닫기 | 중간 자세가 보이고, 마지막 프레임이 씬에 저장된 목표 자세와 일치한다. |
| 개폐 중 반대로 조작하기 | 현재 자세에서 반대 방향으로 움직인다. |
| 탄약고에서 탄 받기 → 삽입 → 닫기 → 다시 열기 → 닫기 → 발사 | 포탄은 기존 규칙에 따라 표시되고, 발사 시 한 번 소비된다. 복구 후 약실은 닫혀 있다. |
| 내부 씬 재진입과 `Bind` 재연결 | 현재 약실 상태에 맞는 자세로 시작하고 이벤트가 중복 재생되지 않는다. |
| Host와 Guest에서 열기·닫기 및 늦은 참가 | 승인된 상태를 기준으로 개폐하며 두 화면의 최종 자세가 일치한다. |
| 컴파일, 씬 참조, Profiler 확인 | 기존 참조가 유효하고, 개폐 중 보간 경로에 불필요한 `GC.Alloc`이 없다. |
