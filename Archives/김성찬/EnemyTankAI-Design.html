설계 방향

하위 AI는 얕은 계층형 상태 머신인 HFSM으로 행동을 선택하고, 이동 및 전투 제어부가 그 결정을 기존 전차 코드의 입력으로 바꾼다. 실제 주행, 포탑과 포신 회전, 약실 조작, 발사체 생성 및 피해 처리는 기존 구현을 최대한 유지한다.

상위 행동 상태는 경계, 교전, 수색, 복귀, 파괴의 5개다. 교전 안에는 접근, 유지, 재배치, 근거리 이격의 4개 하위 상태를 둔다. 탐지, 조준, 장전, 사격을 모두 배타적인 행동 상태로 만들지 않는다. 접근하면서 포탑을 돌리고 장전할 수 있어야 하기 때문이다.

첫 데모의 발사 정책은 유지 상태에서 차체가 충분히 안정되었을 때 발사하는 것으로 정한다. 이동 중 탐지, 조준, 장전은 계속 수행한다. 이동 사격은 추후 발사 조건을 확장하여 추가할 수 있다.

EnemyTank 접두사의 클래스와 아래의 데이터 계약은 신규 설계다. 기존 코드에 이미 구현된 기능으로 해석하지 않는다. Job 배정, 명령 큐, 지휘관의 전술 평가와 네트워크 권한 구현은 현재 범위에 포함하지 않는다.

기존 코드의 재사용 범위

기존 코드 확인한 동작 AI가 추가할 책임
TankMotor 좌우 레버 요청을 저장하고 FixedUpdate에서 가감속과 Rigidbody 속도 적용 목적지와 경로를 좌우 레버 입력으로 변환
TankAim 축 입력에 따라 포탑과 포신 회전, 속도 및 피치 제한 적용 목표 발사 방향 계산과 조준 오차 제어
TankGun 약실 상태, 회복 시간, 조작 요청 승인, 실제 발사 처리 자동 장전 순서 요청과 AI 발사 허가 판단
TankProjectile 발사 조건을 받아 실제 물리 이동, 충돌과 피해 전달 기존 흐름을 유지하며 별도 AI 포탄을 만들지 않음
TankHealth HP와 피격 횟수 갱신, 파괴 시 외형 변화 파괴 후 AI 출력 중단과 피격 사건 해석
TankBallistics 주어진 발사 조건의 궤적과 충돌 예측 목표를 맞힐 발사 방향 역산, 예측 결과의 전술적 해석
TankControl과 TankCrew 로컬 플레이어 역할에 따라 운전, 조준, 장전, 발사 제한 적 입력 경로에서는 사용하지 않고 인간 권한 경로 유지

현재 TankCrew에서는 Driver가 운전하고 Gunner가 조준과 발사를 수행한다. AI가 이 역할을 번갈아 바꾸도록 설계하지 않는다. 플레이어 입력은 기존 TankControl을 거치고, 적 AI는 EnemyTankActuator를 통해 같은 Motor, Aim, Gun을 호출한다.

적 프리팹에는 기존 주행, 조준, 무기, 발사체, 체력 및 필요한 외형 기능을 연결한다. TankInput, 플레이어용 TankControl과 TankCrew, 플레이어 카메라 제어, TankKeyboardDebug는 적 제어 경로에서 제외하거나 비활성화한다. 표시나 입력 컴포넌트를 제외하는 것은 전차 동작을 다시 구현하는 것과 별개다.

의사결정 방식

방식 현재 요구와의 관계 선택
일반 FSM 구현은 가능하나 각 교전 상태에 시야 상실과 파괴 등의 공통 전이가 반복됨 소규모 시작안으로 가능
얕은 HFSM 교전 공통 전이와 이동 전술별 행동을 함께 표현할 수 있음 권장
BT 또는 Utility AI 행동과 선택 기준이 크게 늘어날 때 검토할 수 있음 현재 추가하지 않음

하나의 EnemyTankBrain 안에서 상위 상태와 교전 하위 상태를 관리한다. 상태마다 MonoBehaviour를 만들거나 별도의 범용 FSM 프레임워크를 도입할 필요는 없다. 전이 평가, 상태 진입, 지속 처리, 이탈 처리는 구분한다.

그림의 생존 상태 영역은 파괴 공통 전이를 묶는 영역이다. 별도의 여섯 번째 행동 상태로 세지 않는다.

전체 FSM

상태 이 상태에서 하는 일 상태에 들어올 때 정리할 것
경계 경계점에서 정지하고 주변을 탐지한다. 필요하면 포탑으로 주변을 확인한다. 이전 교전의 이동 목표와 발사 의도를 지운다.
교전 접근·유지·재배치·이격을 선택하며 조준과 장전을 병행한다. 현재 관측과 실행 결과를 보고 교전 하위 상태를 정한다.
수색 마지막 목격 위치로 이동해 제한된 시간 동안 주변을 확인한다. 관측을 잃은 순간의 목격 위치와 수색 종료 시각을 사용한다.
복귀 경계점으로 돌아가며 탐지를 유지한다. 허용 범위 안에서만 방어 교전을 재개한다. 복귀 경로를 요청하고 기존 발사 의도를 해제한다.
파괴 새로운 주행·조준·발사 명령을 차단한다. 레버를 중립으로 바꾸고 조준 입력과 발사 의도를 정리한다.

상위 상태 전이표

상태 변화 언제 바뀌는가 바뀐 뒤 하는 일
경계 → 교전 교전 허용 범위에서 유효한 표적을 발견했을 때 관측한 위치를 기준으로 목표와 교전 하위 상태를 정한다.
교전 → 수색 표적이 보이지 않는 시간이 유예 시간을 넘었을 때 관측 상실 즉시 고정한 마지막 목격 정보를 이어받는다.
교전 → 복귀 추격 시간이나 허용 활동 범위를 넘었을 때 추격을 끝내고 경계점으로 돌아간다.
교전 → 복귀 관측이나 명시적인 결과로 표적의 파괴·소멸을 확인했을 때 교전 대상과 발사 의도를 정리한다.
수색 → 교전 교전 허용 범위에서 표적을 다시 발견했을 때 새 관측으로 이동 전술을 다시 판단한다.
수색 → 복귀 마지막 목격 위치와 주변 확인을 마쳤을 때 수색을 끝내고 복귀한다.
수색 → 복귀 수색 시간·이동 범위·기억 한도 중 하나를 넘었을 때 더 추적하지 않고 복귀한다.
수색 → 복귀 제한된 재시도 후에도 조사 위치에 갈 수 없을 때 실패를 기록하고 복귀 경로를 확인한다.
복귀 → 경계 경계점의 도착 허용 오차 안에 들어왔을 때 레버를 중립으로 바꾸고 주변을 경계한다.
복귀 → 교전 방어 허용 범위 안에서 표적을 발견했을 때 방어 교전을 재개한다. 범위 밖 표적은 다시 추격하지 않는다.
모든 생존 상태 → 파괴 자신의 HP가 0이 되었을 때 새 명령을 차단한다. 실제 출력 직전에도 생존 여부를 확인한다.

짧은 시야 차단은 곧바로 상위 상태를 바꾸지 않는다. 다만 발사는 관측을 잃은 즉시 금지한다. 유예 시간은 상태 왕복을 줄이기 위한 것이며, 가려진 플레이어의 현재 위치를 읽는 허가가 아니다.

비활성화나 제어 주체 해제는 파괴와 구분되는 실행 중단 사건이다. 해당 시점에도 남은 레버와 조준 입력을 정리한다. 재활성화 시 이전 입력을 그대로 재생하지 않고 현재 관측과 상태를 재평가한다.

교전 하위 FSM

마름모는 지속 상태가 아니라 판단 지점이다. 같은 상태가 다시 선택되면 진입 처리를 반복하지 않는다. 채택한 이동 목표도 매 판단마다 새로 뽑지 않고 실패하거나 의미가 없어질 때까지 유지한다.

조건이 겹치면 근거리 이격 → 접근 → 재배치 → 유지 순서로 확인한다. 먼저 안전하게 거리를 벌려야 하는지 보고, 그다음 접근이나 위치 변경이 필요한지 판단한다.

상태 이동 목표 동시에 가능한 기능 초기 발사 정책
접근 적절한 교전 거리에 있는 도달 가능한 위치 탐지, 포탑 추적, 장전 금지
유지 현재 위치 유지 탐지, 조준, 장전, 조건부 발사 차체 안정과 최종 발사 조건 충족 시 허용
재배치 사선이나 발사 각도를 개선하는 가까운 위치 탐지, 포탑 추적, 장전 금지
근거리 이격 후방 또는 측면의 안전한 짧은 이격 위치 탐지, 포탑 추적, 장전 금지

교전 상태 전이표

상태 변화 또는 상황 언제 판단하는가 다음 행동
교전에 들어왔을 때 현재 거리·사격 위치·이동 가능성을 확인한다. 위 우선순위에 따라 하위 상태를 선택한다.
접근·유지·재배치 → 근거리 이격 표적이 이격 시작 거리보다 가까워졌고 안전한 이격 위치가 있을 때 짧게 물러나 거리를 확보한다.
근거리 이격 → 유지 또는 접근 이격 종료 거리까지 벌어졌을 때 현재 위치에서 쏠 수 있으면 유지하고, 거리가 멀면 접근한다.
이격 중 길이 막혔을 때 후방이 막히거나 선택한 위치에 갈 수 없을 때 안전한 대안을 찾는다. 없으면 유지 상태에서 정지하고 간격을 두어 재평가한다.
접근 → 유지 유효 교전 거리와 사격 위치를 확보했을 때 감속해 정지하고 발사 조건을 확인한다.
유지 → 접근 표적이 재접근 기준보다 멀어졌고 접근할 위치가 있을 때 유효 교전 위치로 이동한다.
접근·유지 → 재배치 벽·지형·포신 각도 등의 장애가 지속되고 대안 위치가 있을 때 가까운 다른 사격 위치로 이동한다.
재배치 → 유지 추가 이동이 필요 없어졌거나 목적지에 도착했을 때 정지하고 사격 조건을 다시 확인한다.
이동 중 막혔을 때 길이 막히거나 목적지에 갈 수 없을 때 정해진 횟수 안에서 후보를 바꾸고 경로를 다시 구한다.
이동 후보가 모두 실패했을 때 안전하게 갈 수 있는 대안이 남지 않았을 때 유지 상태에서 정지한다. 발사는 별도 조건으로 판단하고, 간격을 두어 재시도한다.
교전을 끝내야 할 때 상위 상태의 이탈 조건을 충족했을 때 하위 목표를 정리하고 수색·복귀·파괴 등 해당 상위 상태로 전이한다.

유지 상태는 발사 중이라는 뜻이 아니다. 장전 대기, 짧은 아군 통과, 일시적인 차폐, 이동 후보가 없는 상황에서도 정지하며 기다릴 수 있다. 발사 가능 여부는 Combat이 별도로 판단한다.

전이 안정성과 실패 처리

  • 이격 시작 거리보다 종료 거리를 더 크게 둔다.
  • 접근 종료 거리보다 재접근 시작 거리를 더 크게 둔다.
  • 짧은 차폐와 지속적인 사격 장애를 구분한다.
  • 장전 중이라는 이유로 재배치하지 않는다.
  • 상태 최소 유지 시간은 보조 수단으로 사용하며 파괴와 강제 제한을 막지 않는다.
  • 수색점, 재배치점, 복귀점이 막혀도 무한 재탐색하지 않는다.
  • 복귀점 자체가 도달 불가라면 현재 위치에서 안전하게 정지하고 재시도 간격을 둔다. 순간 이동으로 복귀시키지 않는다.

전이 우선순위는 파괴와 실행 중단, 활동 범위 등의 강제 제한, 상위 상태 전이, 근거리 이격, 나머지 교전 전술 순서로 고정한다. 한 번의 판단에서 최종 상위 상태와 필요한 하위 상태를 확정한다.

클래스별 책임과 연결

구조도는 주된 제어와 결과 전달 관계를 나타낸다. 발사 조건과 포구 같은 읽기 전용 정보는 각 제어부가 기존 컴포넌트에서 조회할 수 있다. 기존 컴포넌트의 동작을 변경하는 명령은 Actuator를 통해 전달한다.

신규 클래스 입력 책임과 출력 경계
EnemyTankBrain 관측, 이동 결과, 전투 결과, 설정 HFSM 전이, 이동 목표 채택, 사격 방침, 갱신 순서 관리 Rigidbody나 포탑 Transform을 직접 변경하지 않음
EnemyTankPerception 센서, 대상 식별 정보, 탐지 설정 관측 여부, 관측 위치와 속도, 마지막 목격 정보 보이지 않는 표적의 현재 위치를 다른 제어부에 제공하지 않음
EnemyTankNavigation 목표 위치, 차체 상태, 허용 범위 경로와 조향 계산, 레버, 도착과 실패 결과 전술 상태나 공격 대상을 임의로 바꾸지 않음
EnemyTankCombat 관측 표적, 포구, 무기 상태, 사격 방침 탄도 조준, 자동 장전 요청, 최종 발사 판단, 불가 이유 이동 목적지를 직접 변경하지 않음
EnemyTankActuator 레버, 조준 축, 무기 요청, 자신의 생존 상태 기존 API 호출, 회복 갱신, 출력 중단 로컬 AI의 단일 제어 경계이며 네트워크 권한 체계 전체를 대신하지 않음

TankTargetInfo 진영, 관측 지점, 조준 지점, Health 참조 최소한의 표적 식별 정보 신규 식별용 컴포넌트이며 복잡한 팀 전술 시스템은 아님

EnemyTankBrain이 관리하는 작은 데이터 구조를 두되 작성 책임은 고정한다. 모든 기능이 하나의 공용 정보를 자유롭게 덮어쓰게 만들지 않는다.

기능별 구현 방식

탐지와 기억

첫 데모는 전차 센서 기준점에서 360도 거리 및 차폐 검사를 사용하는 출발안을 권장한다. 시야각 제한은 이후 설정으로 조정할 수 있다. 등록된 플레이어 전차를 대상으로 시작하고, 여러 표적이 필요해지면 후보 검색과 대상 선택을 확장한다.

Unity 물리 검사로 거리와 차폐를 확인한다. 여러 후보가 있는 경우 범위 검색으로 후보를 얻고 실제 관측은 Raycast로 확인한다. 자신의 콜라이더와 관측 대상의 콜라이더를 구분하고, 여러 차체 콜라이더가 같은 표적으로 중복 등록되지 않게 한다.

실제로 보이는 동안에만 위치와 속도를 갱신한다. 속도는 관측 위치의 시간 변화로 추정할 수 있다. 재발견 시 속도 추정을 초기화하고 연속된 관측으로 다시 추정한다. 시야를 잃으면 마지막 목격 위치를 고정하고, 다른 기능은 이 관측 데이터만 사용한다. 발사 직전에는 최신 차폐 상태를 다시 확인한다.

현재 TankHealth의 피격 횟수 변화로 맞았다는 사실은 확인할 수 있지만, 공격자의 위치와 방향은 알 수 없다. 피격 시 경계를 높이고 탐지를 재확인하되 공격자 위치를 자동으로 알아내지 않는다. 방향성 반격이 필요해질 때 피해 알림 데이터를 확장한다.

교전 위치와 주행

Brain이 접근, 재배치, 이격의 목적을 정한다. Navigation이 소수의 위치 후보와 도달 가능성을 제공하고 Combat이 사격 조건을 평가한다. Brain은 가까운 유효 후보를 채택한 뒤 Navigation에 실행을 맡긴다. 현재는 복잡한 점수 체계보다 유효성 우선의 선택이면 충분하다.

NavMesh.CalculatePath로 경로 코너를 얻고 기존 TankMotor로 실제 주행한다. 전차용 agent type과 폭을 반영한 NavMesh 준비 및 맵 검증이 필요하다. 경로 반환값뿐 아니라 PathComplete, PathPartial, PathInvalid를 구분한다.

  • 방향 오차가 크면 감속하고 제자리 선회한다.
  • 정렬되면 다음 코너를 향해 전진한다.
  • 현재 속도와 감속 성능을 반영해 도착 전에 제동한다.
  • 원하는 전진값 f와 선회값 t를 왼쪽 f+t, 오른쪽 f-t로 변환하고 필요하면 함께 정규화한다.
  • 후진은 후방 여유를 확인한 뒤 제한된 거리만 허용한다.
  • 실제 이동 명령에 비해 일정 시간 진척이 없을 때 막힘으로 판단한다. 정지와 제자리 선회는 제외한다.
  • 앞차나 벽이 가까우면 감속 또는 정지하고, 일정 시간 뒤 경로와 후보를 재평가한다.

경로 계산은 필요할 때 갱신하고 매 프레임 반복하지 않는다. NavMeshAgent가 Rigidbody와 함께 실제 위치를 변경하게 하지 않는다. 경로 계산만 사용하는 구성에는 자동 군중 회피가 없으므로, 차체 크기의 근거리 검사와 기본적인 정지 및 재시도 처리가 필요하다.

탄도 조준

Combat 내부의 작은 BallisticAimSolver가 목표를 맞힐 발사 방향을 구한다. 별도의 MonoBehaviour를 여러 개 추가할 필요는 없다.

입력은 관측 목표점, 현재 포구 위치, 실제 포탄 속도, 중력, 고정 시간 간격, 포탄 수명과 피치 제한이다. 출력은 목표 발사 방향, 예상 비행시간, 도달 가능 여부와 실패 이유다.

정지 목표의 저각 해를 초기값으로 구하고 기존 TankBallisticStep과 같은 적분으로 오차를 확인하고 보정한다. 현재 TankGun의 초속도는 포구 방향에 ProjectileSpeed를 곱한 값이므로 차체 속도를 임의로 더하지 않는다. 포탑 회전에 따라 포구 위치도 달라질 수 있으므로 현재 포구 기준으로 반복 갱신한다.

현재 포구 방향과 목표 발사 방향의 yaw 및 pitch 오차를 축 입력으로 변환한다. 실제 회전은 TankAim.ApplyInput에 맡기고 포탑과 포신의 Transform을 AI가 직접 덮어쓰지 않는다. 한계 각도나 수명 밖 목표는 조준 실패로 반환한다.

검증은 정지 목표부터 시작한다. 이후 실제 관측 속도와 예상 비행시간을 이용한 단순 선행 조준을 추가한다. 표적이 가려진 뒤 실시간 Transform을 읽어 예측을 보정하지 않는다.

TankBallistics.Predict는 현재 발사 방향의 궤적 및 환경 충돌 검사에 재사용한다. 움직이는 표적에 선행 사격할 때 현재 월드의 표적 콜라이더를 반드시 먼저 맞혀야 한다는 조건을 걸면 정상적인 선행 조준까지 거부할 수 있다. 탄도 안전과 명중 가능성을 구분한다.

첫 버전은 기존 예측 컴포넌트와 공개 Predict를 그대로 사용한다. ShowMarker를 꺼도 자동 계산은 남는다. 실제 중복 호출이나 부하가 문제가 되는 것이 확인되면 계산을 다시 구현하는 대신 자동 갱신과 요청 시 계산 모드를 작게 분리한다.

자동 장전과 사격

실제 약실 상태의 원본은 TankGun.State 하나로 유지한다. AI는 상태에 맞는 요청을 보내며 동일한 회복 타이머를 따로 구현하지 않는다.

약실 상태 AI의 동작
EmptyOpen RequestInsert 요청
LoadedOpen RequestClose 요청
EmptyClosed RequestOpenEmpty 요청
Ready 최종 발사 조건을 만족할 때만 RequestFire 요청
Recovering TickRecovery를 호출하며 회복 완료 대기

Actuator가 갱신 시작 시 TickRecovery를 호출한다. 현재 플레이어 입력 경로에서는 TankControl이 맡던 책임이다. 상태에 맞지 않는 요청을 매 프레임 반복하지 않으며, 한 갱신에서 발사 요청은 최대 한 번 보낸다. 요청 실패를 발사 성공으로 기록하지 않는다.

현재 삽입과 폐쇄는 즉시 상태를 바꾸고 RecoveryDuration은 테스트용 회복 시간이다. 최종 장전 시간이나 장전 연출은 별도의 게임 규칙으로 결정한다.

최종 발사는 다음 조건을 모두 통과해야 한다.

확인할 내용 통과 조건
생존과 제어 자신이 살아 있고 AI 제어가 활성화되어 있다.
교전 상태 상위 상태가 교전이고, 초기 정책상 하위 상태가 유지다.
차체 안정 차체의 이동·회전 속도가 안정 기준 안에 있다.
표적 관측 유효한 표적이 현재 보이며, 발사 직전에도 시야가 확보된다.
반응과 조준 반응 지연이 지났고 조준 오차가 허용 범위 안이다.
포구와 탄도 유효한 발사 해가 있고, 포구가 외부 물체와 겹치지 않으며, 궤적이 지형에 막히지 않는다.
아군 안전 예상 교전 구간에서 아군이 궤적을 막지 않는다.
무기 승인 TankGun.CanFire를 확인하고 요청한다. 실제 RequestFire가 성공해야 발사 성공으로 처리한다.

장전 중, 조준 중, 일시적인 아군 통과, 지속적인 벽 차단, 탄도 해 없음 등의 사격 불가 이유를 구분한다. 이 중 장전과 일시 차단은 재배치 이유가 아니다.

아군 사선 검사는 발사 직전의 보류 기능이다. 발사 후 아군이 궤도로 들어오는 상황까지 막지는 않는다. 아군 피해 자체를 허용할지는 진영별 피해 규칙으로 별도 결정한다.

파괴와 비활성 처리

자신의 파괴 여부는 판단 주기와 별개로 실제 출력 직전에도 확인한다. 파괴 시 새 발사와 조준을 차단하고 Motor에 중립 입력을 보낸다. AI를 비활성화하거나 제어를 해제할 때도 같은 입력 정리를 수행한다.

현재 Motor의 중립 입력은 감속 정지다. 파괴 순간 즉시 위치를 고정하는 기능이 아니다. 즉시 정지, 관성 유지, 충돌 가능한 잔해 등의 정책은 별도로 정한다. 기존 TankHealth가 자동으로 주행과 발사를 정지시키는 것으로 가정하지 않는다.

실행 순서와 갱신 주기

EnemyTankBrain이 한 곳에서 순서를 관리하고 다른 제어부는 호출에 따라 처리한다. 여러 컴포넌트가 독립 Update에서 같은 입력을 서로 덮어쓰게 만들지 않는다.

처리 순서는 준비 확인 → 관측과 판단 → 입력 계산과 적용 → 최종 발사 검사다.

처리 단계 이 단계에서 하는 일
준비 확인 Actuator가 무기 회복을 갱신하고 자신의 생존 여부를 확인한다.
관측과 판단 필요한 주기에 관측을 갱신한다. 이전 이동 결과와 현재 전투 조건을 보고 FSM 상태·이동 목표·사격 방침을 정한다.
입력 계산과 적용 Navigation은 레버를, Combat은 조준 입력을 계산한다. Actuator가 이를 기존 주행·조준 기능에 적용한다.
최종 발사 검사 변경된 포구 방향으로 안전 조건을 다시 확인한 뒤 장전 또는 발사를 요청한다.

Motor의 실제 물리 이동은 기존 FixedUpdate가 담당한다. 판단 빈도, 센서 갱신, 프레임별 조준 실행을 구분한다. 낮은 판단 빈도 사이에도 파괴 후 발사나 남은 레버 입력이 실행되지 않아야 한다.

구현 순서와 단계별 완료 기준

개발 순서는 전차 제어 연결 → 탐지와 기억 → 정지 교전 → 목적지 이동 → FSM 연결 → 예외 처리 → 부하와 기존 기능 확인으로 잡는다.

구현할 기능 확인할 상황 다음으로 넘어갈 수 있는 기준
전차 제어 연결 적 프리팹과 Actuator에 시험 입력을 보내 주행·조준·장전·발사를 확인한다. 기존 코어로 동작하고 플레이어 입력과 충돌하지 않는다. 중단 시 남은 입력이 정리된다.
탐지와 기억 표적 식별과 Perception을 붙여 거리 밖·차폐·재발견·피격을 확인한다. 가려진 실제 위치를 기억이 따라가지 않는다. 피격만으로 공격자 위치를 얻지 않는다.
정지 교전 Combat으로 거리·높이가 다른 정지 목표를 확인하고, 이후 일정 속도 이동 목표를 확인한다. 실제 탄도로 명중하며 장전·조준 조건을 지킨다. 제한 밖 목표에는 실패 이유를 제공한다.
목적지 이동 Navigation으로 코너·제동·후진·막힘·부분 경로를 확인한다. 순간 이동이나 순간 회전 없이 도착한다. 실패하면 제한된 복구 뒤 정지한다.
FSM 연결 발견부터 접근·유지·재배치·이격·수색·복귀까지 이어 본다. 지휘관 없이 전체 흐름을 수행하며 같은 상태의 진입 처리를 중복하지 않는다.
예외와 복수 전차 짧은 차폐·아군 통과·거리 경계·후보 실패·이동 중 파괴를 확인한다. 상태 왕복과 무한 재탐색이 없다. 장전 때문에 재배치하거나 파괴 후 새로 발사하지 않는다.
부하와 기존 기능 확인 6대 동시 이동, 50대 배치와 동시 행동 증가, 플레이어 조작을 비교한다. 목표 환경에서 병목을 분리해 측정하고, 공유 코어와 플레이어 권한 동작을 유지한다.

정지 교전에서는 적이 관측한 목표를 조준하고 연속 장전·발사하는 작은 단위부터 검증한다. 이동과 FSM 전체를 붙이기 전에 조준과 발사 조건의 문제를 따로 확인할 수 있다.

최종 수용 검증 항목

  • 경계 중 플레이어를 발견하면 교전을 시작하고, 반응 지연과 발사 조건을 충족한 뒤 사격한다.
  • 이동, 포탑 추적, 장전이 동시에 가능하며 초기 정책상 이동 사격은 하지 않는다.
  • 장전 중이라는 이유만으로 재배치하지 않는다.
  • 한 번의 짧은 차폐로 교전과 수색을 반복하지 않지만 발사는 즉시 보류한다.
  • 가려진 플레이어가 옆으로 움직여도 마지막 목격 위치가 갱신되지 않는다.
  • 시야는 확보되지만 포구나 탄도가 막힌 상황을 구분한다.
  • 아군 통과 시 발사만 보류하며, 차단이 풀리면 정상 교전한다.
  • 거리 경계에서 전진과 후진을 반복하지 않는다.
  • 이동 불가, 재배치 후보 실패, 복귀점 도달 불가 상황에 재시도 한도가 있다.
  • 파괴와 AI 비활성 시 마지막 레버 입력을 정리하고 신규 발사를 차단한다.
  • 플레이어의 기존 역할 권한, 주행, 조준, 장전과 발사가 유지된다.

상태 전이 사유, 관측 여부와 마지막 목격 시각, 이동 목표 및 실패 이유, 발사 보류 이유를 확인할 수 있게 한다. 매 프레임 로그 대신 상태 변화와 주요 결과를 기록한다. 기존 플레이어 검증 결과는 적 AI의 완료 증거를 대신하지 않는다.

지휘관 연결과 현재 범위

구분 현재 구현 지휘관 추가 시
목표와 행동 범위 자율 정책이 경계점, 추격 한도와 교전 정책 제공 지휘관이 방어 지점, 이동 목표, 행동 범위와 정책 제공
하위 전술 접근, 유지, 재배치, 근거리 이격과 제한 수색 같은 행동 재사용, 명령별 중단 조건과 제약 확장
관측 전차 자신의 관측과 기억 필요할 때 공유 정보의 출처와 유효성을 구분하여 확장
실제 실행 Navigation, Combat, Actuator와 기존 전차 기능 대부분 재사용
배정과 보고 구현하지 않음 필요해질 때 Job, 배정과 보고 체계 설계

지휘관은 목적과 제약을 전달하고, 하위 AI가 이동과 교전을 수행한다. 지휘관이 좌우 레버나 발사 함수를 직접 호출하여 두 제어 주체가 충돌하게 만들지 않는다. 자율 정책이 목표를 만드는 부분과 그 목표를 실행하는 부분을 분리하는 것이 현재 필요한 확장 지점이다.

총 전차 수 약 50대와 통상 동시 이동 약 6대는 잠정 규모다. 이동 대수, 교전 대수, 탐지 대수, 화면에 보이는 대수를 구분하여 측정한다. 동시 행동이 늘어나는 조건도 별도로 확인한다. 성능 수용 기준은 실행 환경과 목표 프레임을 확정한 뒤 정한다.

50대라는 이유만으로 기존 Motor나 Gun을 다시 구현하지 않는다. 우선 재사용 구조로 기능을 완성하고 실제 환경에서 AI 판단, 경로, 탄도, 물리, 렌더링의 비용을 분리해 확인한 뒤 해당 부분을 조정한다.
