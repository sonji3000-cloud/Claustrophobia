# HP·파괴 중단·통합 확인

적 전차는 기존 `TankHealth`로 피해를 받는다. HP가 0이 되면 `Died` 이벤트가 한 번 발생하고, `TankAI.StopActions()`가 즉시 이동·조준 입력과 예약된 AI 무기 요청을 지운다. 다음 AI 틱을 기다리지 않는다.

## Unity에서 확인하기

1. Play를 끈다. Project 창에서 **TankAIIntegrationTest**를 검색해 `Assets/TankPrototype/Scenes/TankAIIntegrationTest.unity`를 더블클릭한다.
2. Hierarchy 상단이 **TankAIIntegrationTest**인지 확인하고 Play를 누른다. `TankMoveTest`는 이동 전용, `TankAttackTest`는 공격 전용이다.
3. **Tank AI Integration Demo** 오브젝트를 선택한다. Inspector의 `TankAttackDemo` 컴포넌트 아래에서 상태와 시험 버튼을 확인한다. NetworkRunner는 별도 오브젝트이므로 이 Demo는 실행 중에도 씬에 남는다.
4. 자동으로 **이동 → 목적지 도착·정지 → 지정 표적 조준·장전·발사** 순서로 진행한다.
5. **공격받는 표적 HP**가 `100 → 75 → 50 → 25 → 0`으로 줄어드는지 확인한다. HP 0에서는 `TargetDown`으로 전환하며 추가 발사를 멈춘다. **적 전차 자신의 HP**는 100으로 남아 있어야 한다.

Inspector의 항목은 다음처럼 구분한다.

| 항목 | 확인할 내용 |
| --- | --- |
| 이동 상태 | `Moving → Arrived`; 공격을 시작하면 이동 명령은 `Idle`로 정리됨 |
| 공격 상태 | 조준·장전·발사 후 표적 HP 0에서 `TargetDown` |
| 실제 발사 수 | 명령 요청 수가 아니라 실제 포탄 생성에 성공한 횟수 |
| 적 전차 자신의 HP | 이동·공격하는 Sherman의 HP |
| 공격받는 표적 HP | 앞에 배치된 `Attack Target`의 HP |
| 적 전차 파괴 횟수 | 자신이 파괴된 뒤 1을 유지 |
| 파괴 후 중단 검사 | 자기 파괴 후 `PASS: stopped; new commands rejected`인지 확인 |

## 적 전차 자신을 파괴해 보기

이 시험은 일반 포탄 명중 시험과 별도로, **직접 HP 함수를 호출하는 시험용 버튼**이다. Console에도 포탄 충돌을 거치지 않은 시험 피해라고 표시한다.

| 시험 | 조작 | 기대 결과 |
| --- | --- | --- |
| 일반 피해 | **적 전차 HP -25 (시험용)**를 누른다. | 자신의 HP만 25 감소하며 살아 있는 동안 이동·공격을 계속한다. |
| 이동 중 파괴 | Play를 재시작하고 이동하는 동안 **적 전차 파괴 (시험용)**를 누른다. | 즉시 이동 중단. 목적지에 도착한 뒤 공격하는 예약도 취소된다. |
| 조준·장전·공격 중 파괴 | Play를 재시작하고 공격이 시작되면 **적 전차 파괴 (시험용)**를 누른다. | 조준 입력과 미실행 무기 요청 제거. 새 장전·발사·회복 처리 중단. |
| 파괴 후 명령 | 자기 파괴 직후 검사 결과를 확인한다. | 이동, 레버, 조준, 표적 공격, 발사 명령이 모두 거부되어 PASS가 표시된다. |

파괴 시 수평 이동과 회전을 멈추며 중력에 의한 낙하는 유지한다. 차체와 Collider는 잔해로 남고 렌더러가 어두워진다. 이미 발사된 포탄은 계속 날아가며 피해를 줄 수 있다. 따라서 파괴 직후 발생한 마지막 명중만으로 새 발사가 있었다고 판단하지 말고 **실제 발사 수**가 늘어나는지 확인한다.

상태를 초기화하려면 Play를 껐다 다시 켠다. 살아 있는 전차의 이동·공격을 다시 명령하려면 **이동 후 공격**, **지정 표적 공격** 버튼을 사용한다. **전체 중지**는 이동과 공격 예약을 함께 취소한다.

## 구현 범위

- `TankHealth`의 기본 HP는 100이다. 피해는 유한한 양수만 받으며 HP는 0 아래로 내려가지 않는다. 이미 파괴된 대상에 추가 피해를 줘도 HP·피격 횟수·파괴 횟수가 늘지 않는다.
- 비활성 Health에 대한 피해를 거부한다. 잘못된 초기 MaxHP는 100으로 보정한다.
- NetworkObject가 있는 전차는 Spawn 완료, 실행 중인 서버 Runner, StateAuthority를 모두 확인한 뒤 HP를 변경한다. NetworkObject가 없는 기존 로컬 테스트 표적은 로컬 피해 처리를 유지한다.
- `Died` 이벤트는 HP와 피격 기록을 확정한 뒤 한 번 호출한다. 적 AI가 이벤트를 구독해 즉시 `StopActions`를 실행하고, 비활성화할 때 구독을 해제한다.
- `TankGun`도 AI가 행동할 수 없으면 요청을 버리고 회복·장전·발사 처리를 진행하지 않는다. `CanFire`는 false가 된다.
- 표적이 먼저 파괴되면 공격자는 `TargetDown`에서 멈춘다. 자신의 HP가 0이 되면 이동·공격 상태를 `Idle`로 정리하고 새 명령을 거부한다.
- 피해 발생은 기존 `TankProjectile` 충돌 경로를 사용한다. 실제 포탄은 한 번 종료된 뒤 다시 피해를 처리하지 않는다. AI가 직접 표적의 HP를 깎지는 않는다.

**HP 값과 파괴 표시를 게스트에 전달하는 네트워크 동기화는 이번 변경에서 추가하지 않았다.** 호스트의 HP 변경 권한과 AI 중단을 구현했으며, HP·피탄 동기화 담당 작업에서 같은 `TankHealth` 상태를 연결해야 한다. 차체·조준·포탄의 기존 동기화 경로는 유지한다.

## 수행한 검증

런타임과 Editor 어셈블리 C# 컴파일을 통과했다. 기존 경고 2건 외 새 컴파일 오류는 없다.

`Builds/TankHPIntegration`의 검사는 실제 `TankAI`, `TankMotor`, `TankAim`, `TankGun`, `TankHealth`, `TankAimSolver` 소스를 함께 컴파일·실행한다. HP·통합 9개, 공격 10개, 이동 회귀 14개로 총 33개 검사 그룹을 통과했다. 결과는 `Builds/TankHPIntegration/logic-results.txt`에 저장했다.

엔진·Fusion 서비스는 대체 객체를 사용한다. 통합 로직 검사에서 명중은 생성된 시험 포탄의 피해를 Health에 전달하는 방식으로 처리했으며, 네이티브 PhysX 충돌이나 Fusion 통신을 실행한 검사는 아니다. Unity Play Mode의 실제 씬 실행·명중과 세 클라이언트 동시 접속 검증은 별도로 남아 있다.

기존 `TankTest`, `TankMoveTest`, `TankAttackTest` 씬 파일과 Sherman 모델·프리팹 배치는 변경하지 않았다. 기존 공격 Demo 스크립트와 Inspector에 통합 시험 기능을 추가하고 별도의 `TankAIIntegrationTest` 씬에서 이동 후 공격을 켰다.
