# TankTest 적 AI 네트워크 시험 패널

`TankTest`의 기존 3인 Fusion 세션에서 호스트가 적을 생성하고 사각 순찰·정지·고정 표적 공격을 시키는 시험 도구다. Game 화면과 PC 실행 파일의 오른쪽 위에 표시된다. 별도의 Single 세션을 시작하지 않는다.

## 실행 순서

1. Unity에서 Play를 끄고 **`Assets/TankPrototype/Scenes/TankTest.unity`**를 다시 연다. Hierarchy에 **Enemy AI Network Test**가 추가되어 있어야 한다.
2. Play를 누른다. 기존 `SessionJoinInit`이 세션을 시작한다. 접속 후 오른쪽 위 **적 AI 네트워크 시험** 패널에 `HOST · 조작 가능` 또는 `CLIENT · 관찰 전용`이 표시된다.
3. 호스트에서 **적 생성 / 초기화**를 누른다. 시험용 Sherman 한 대와 고정 표적 하나가 네트워크 생성되며 큰 관찰 화면이 각 클라이언트에서 자동으로 열린다. 자동으로 적을 생성하지는 않는다.
4. **사각 순찰 시작**을 누른다. 첫 지점에 생성된 적은 곧바로 2번으로 출발해 **2 → 3 → 4 → 1 → 2…** 순서로 반복한다. 클라이언트는 같은 적 ID와 움직임을 확인한다.
5. **전체 정지**를 눌러 이동·공격이 멈추는지 확인한다. 코너에서 기다리는 중에 눌러도 이후 순찰이 재개되면 안 된다.
6. **지정 표적 공격**을 누른다. 순찰을 취소하고 고정 표적을 조준·장전·공격한다. 표적을 파괴하면 `TargetDown`에서 멈춘다.
7. 다시 시험하려면 **적 생성 / 초기화**를 누른다. 기존 시험 적·표적과 그 적이 발사한 남은 포탄을 정리한 뒤 새로 생성한다. 플레이어와 다른 오브젝트·포탄은 건드리지 않는다.

관찰 화면은 각 클라이언트가 자기 씬을 실제로 렌더링한 화면이다. 호스트 영상을 전송하는 방식이 아니므로 원격 적의 위치·회전을 직접 비교할 수 있다. 생성·초기화 시 자동으로 켜지고 **시험 구역 화면 보기 / 닫기**로 조작할 수 있다. 기존 플레이어 카메라는 바꾸지 않는다. 관찰 화면에는 각 순찰 지점의 번호도 표시한다. 패널 제목을 누르면 접거나 펼칠 수 있다. 마우스가 내부 시점에 잠겨 있다면 F8로 외부 모드로 전환한 뒤 버튼을 누른다. 기존 외부 관찰 키인 **F8 → F4**도 그대로 사용할 수 있다.

**예전에 빌드한 exe에는 새 패널이 없다.** 이번 변경을 포함해 PC 빌드를 다시 만들고 모든 접속자에게 같은 버전을 전달해야 한다. 서로 다른 코드·씬·프리팹 버전으로 접속해 비교하지 않는다.

## 버튼과 표시 값

| 버튼 | 동작 |
| --- | --- |
| 적 생성 / 초기화 | 적 1대와 고정 표적 1개를 호스트가 `Runner.Spawn`으로 생성. 재실행 시 기존 시험 대상을 교체 |
| 사각 순찰 시작 | 실제 차체가 목표의 XZ 반경 1m 안에 도착하면 정지 후 0.1초 대기하고 다음 번호로 이동 |
| 전체 정지 | 순찰 예약과 AI 이동·조준·무기 요청을 취소 |
| 지정 표적 공격 | 순찰 예약을 취소하고 고정 시험 표적을 공격. 플레이어 Tiger를 겨냥하지 않음 |
| 시험 구역 화면 보기 / 닫기 | 이 클라이언트의 시험 구역 관찰 화면을 켜거나 끔. 호스트 권한 없이 사용 가능 |

클라이언트에서는 조작 버튼이 비활성화된다. 호스트 여부는 역할 자리와 별개이며, 운전수·포수·전차장 중 누구든 세션 호스트일 수 있다.

패널은 시험 상태, 현재 지점, 완주 횟수, 적 네트워크 ID, 관찰 중인 위치, 포탑·포신 각도와 실제 발사 수를 표시한다. 완주 횟수는 네 지점을 돌아 첫 지점에 다시 도착했을 때 증가한다. 이동·공격 상태는 호스트에서 복제한 진단 값이다. 클라이언트의 AI를 직접 실행해서 구하지 않는다.

HP는 **호스트 화면에만** 적·표적 값을 표시한다. 현재 HP 값과 파괴 색상은 아직 게스트에 공유되지 않는다. 따라서 이번 단계의 클라이언트 비교 항목은 생성·제거, 차체 이동·회전, 포탑·포신 회전, 포탄과 발사 수, 정지 결과다. HP·피탄 공유는 별도 동기화 작업으로 연결한다.

## 네트워크 담당자 확인 항목

| 순서 | 호스트 조작 | 각 화면에서 확인 |
| --- | --- | --- |
| 1 | 세 명이 같은 TankTest 세션에 접속한 뒤 적 생성 | 시험 적과 표적이 하나씩 보이고 적 ID가 동일함 |
| 2 | 사각 순찰 시작, 두 바퀴 이상 관찰 | 이동·회전·코너 정지가 계속 전달되며 원격 AI가 별도로 움직이지 않음 |
| 3 | 이동 중 및 코너 대기 중 전체 정지 | 모든 화면에서 적이 멈추고 뒤늦게 다시 출발하지 않음 |
| 4 | 지정 표적 공격 | 포탑·포신 방향, 포탄 생성과 발사 수가 전달됨. 호스트에서 표적 HP 감소 확인 |
| 5 | 포탄이 날아가는 중 초기화 | 새 적·표적으로 교체되며 기존 시험 포탄이 새 표적을 때리지 않음 |
| 6 | 순찰이 진행 중인 세션에 나머지 클라이언트 접속 | 기존 적을 중복 생성하지 않고 진행 중인 적을 관찰함 |

실시간 전송과 보간 때문에 위치 수치가 프레임마다 완전히 같을 필요는 없다. 같은 적을 같은 경로로 관찰하는지, 멈춘 뒤 위치가 수렴하는지 확인한다. 이 표는 실제 다중 접속에서 수행할 절차이며, 아래 로직 검사만으로 실제 통신을 통과했다고 판단하지 않는다.

## 구성과 개발 경계

- 씬 루트 **Enemy AI Network Test**의 `TankAINetworkTest`가 기존 `SessionJoinInit`을 명시적으로 참조한다. Runner와 같은 오브젝트에 붙이지 않아 DontDestroyOnLoad로 함께 이동하지 않는다.
- 이 루트는 Scene NetworkObject다. 생성한 적·표적 참조와 시험 상태를 Networked 값으로 공유하므로 나중에 접속한 클라이언트도 같은 대상을 식별할 수 있다.
- UI 명령은 호스트에서만 접수하고, 다음 `FixedUpdateNetwork`에서 실행한다. 순찰도 호스트 틱에서 기존 `TankAI.MoveTo`를 호출한다.
- 적이 파괴되거나 세션 준비 상태가 해제되면 예약된 명령과 순찰을 중단한다. 생성 도중 실패하면 부분 생성된 시험 대상도 정리한다.
- 기존 `EnemyTank-Sherman.prefab`을 그대로 사용한다. 고정 표적은 기존 `TankTarget`을 바탕으로 만든 `TankAINetworkTestTarget.prefab`이며, 네트워크 생성과 Transform 공유만 추가했다.
- 시험 적을 교체할 때 그 적이 발사한 포탄만 식별하기 위해 `TankProjectile.SourceGun` 읽기 전용 참조를 추가했다. 피해·충돌·발사 로직은 변경하지 않았다.
- 기존 TankTest 오브젝트·배치·세션 코드는 유지했다. 새 제어 루트, 생성 위치, 순찰 표시와 관찰용 카메라만 추가했다. 카메라는 관찰 화면을 켰을 때만 전용 RenderTexture로 렌더링하며, AudioListener를 추가하지 않았다. 원래 은신용 Sherman들과 플레이어 전차는 시험 대상이 아니다.
- 이는 네트워크 시험용 명령 실행기다. 정찰·추격·전투 판단을 선택하는 본격적인 FSM이나 장애물 우회 기능은 추가하지 않았다.

기본 순찰 월드 좌표는 `(43, -35) → (55, -35) → (55, -23) → (43, -23)`이며 XZ 기준 한 변 12m다. 실제 네트워크 Tiger 앞쪽의 빈 구역으로 옮겼다. 제어 루트는 `(41, 0, -41)`, 적 생성 위치는 `(43, 0.15, -35)`, 고정 표적 위치는 `(47, 0, -13)`이다. 좌표를 바꾸려면 제어 루트 아래의 `AI Spawn Point`, `Patrol Point 1~4`, `AI Target Spawn Point` Transform을 수정한다.

네트워크 시험 적에만 빠른 시험 설정을 적용한다. 최대 이동 속도 6m/s, 이동 가속·감속 8·10, 최대 회전 속도 120도/s, 회전 가속·감속 360이다. 원본 프리팹과 개별 이동 시험 씬의 설정은 바꾸지 않는다. 제어 컴포넌트의 `Fast Test Movement`를 끄면 기본 프리팹 값을 사용한다.

순찰 지점 전환은 일반 AI의 엄격한 `Arrived` 플래그만 기다리지 않고 실제 차체와 현재 목표 간 거리로 판단한다. 자체 경로 인덱스를 유지해 다음 지점을 1·2·3·4 순서로 결정한다. 코너의 작은 회전 잔여값 때문에 다음 지점으로 넘어가지 못하는 상황을 피하기 위한 처리다.

패널에는 호스트의 **현재 목표 번호, 남은 거리, 실제 수평 속도, 물리 틱 수, Kinematic 여부**도 표시한다. 목표를 전달할 때 `[AI PATROL]` 로그를 한 번 남기며, 3초 동안 차체가 거의 이동하지 않으면 물리 상태를 한 번 경고한다. 이동 명령이 거절되면 `Rigidbody is kinematic` 등 실제 차단 사유를 표시한다. 호스트 AI는 동적 Rigidbody를 유지하고 구동 입력이 있을 때 모터가 Rigidbody를 깨운다. 클라이언트는 동적 모터를 실행하지 않는다.

## 검증 결과

런타임·Editor C# 컴파일 및 Fusion ILPostProcessor 처리를 통과했다. 새 Networked 속성의 코드 생성도 검사했다. 런타임 컴파일에는 기존 경고 2건이 남아 있다.

`Builds/TankAINetworkTest`에서 실제 제어기·AI·이동·조준·무기·HP 소스를 함께 실행한다. 패널 검사에는 2번 코너의 회전 잔여값, 잘못된 목표의 도착 플래그, 호스트 Kinematic 복구 및 두 바퀴 동안의 정확한 지점 순서를 포함한다. 기존 공격·HP·이동 회귀 검사도 함께 실행한다. 결과는 `logic-results.txt`를 확인한다.

이 검사에서 엔진·Fusion 서비스와 포탄 충돌은 대체 객체를 사용했다. Unity Game 화면의 패널 배치·지형 충돌·씬 실행과 실제 3클라이언트 통신·늦은 접속은 별도로 확인해야 한다. 결과는 `logic-results.txt`, Fusion 코드 생성 결과는 `weaver-results.txt`에 저장한다.
