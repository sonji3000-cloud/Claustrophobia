# 적 전차 AI 개발·시험 가이드

기준일: 2026-11-13. 적 프리팹 구성, 호스트 실행, 직선·NavMesh 경로 이동, 지정 표적 공격, HP·파괴 중단과 시험 방법을 한곳에 정리한다.

현재 공용 기능은 **지정 지점까지 직선 또는 NavMesh 경로로 이동·정지하고, 경로 이동이 막히면 제한적으로 재탐색하며, 지정 표적을 조준·장전·반복 공격하고, 파괴되면 행동을 중단하는 것**이다. 이후 하위 AI는 상황을 판단해 같은 명령을 호출하도록 확장한다. 자동 표적 탐지, 추격 판단, 후진 탈출과 상세 FSM은 아직 구현하지 않았다. 실제 벽 접촉·주행 확인은 아래 Play Mode 순서로 진행한다.

## 시험장·공용 경로 이동의 현재 완료 범위

시험장·베이크 → 공용 경로 추종 → 실패·명령 변경 처리 → 이동·공격 통합 연결까지 구현했다. 사용자가 앞선 시험 동작을 확인했다고 알려 주었고, 자동 검사는 현재 공용 소스로 총 96개를 통과했다. 새 통합 버튼의 실제 발사·접촉 확인과 3인 NavMesh 주행 비교는 아래 수동 확인 범위다.

| 바로 사용할 대상 | 용도 |
| --- | --- |
| `TankAIIntegrationTest` / `Tank AI Integration Demo` | 평지 NavMesh, 구역 이동·정체·명령 변경·이동 후 공격 확인 |
| `TankTest` / `Enemy AI Network Test` | 기존 3인 세션에서 생성·직선 순찰·공격 결과 공유 확인 |
| `EnemyTank-Sherman` + `TankAI` + `TankPath` | 실제 맵과 이후 탐지·FSM에서 재사용할 공용 전차 기능 |

맵에는 `TankFlat` Agent와 물리 충돌체를 기준으로 NavMesh를 새로 생성한다. 호스트에서 적을 Spawn한 뒤 `SetMoveMode(NavMesh)`를 한 번 호출하고, 행동을 변경할 때 `MoveTo()`를 전달한다. `Arrived`, `Failed`, 재시도 상태를 확인해 다음 행동을 결정한다. 공용 모터의 완만한 지형 대응은 아래 2단계까지 적용했다. 현재 TankFlat NavMesh는 평지 설정을 유지한다. 실제 맵의 회전 공간과 경사 경로 연결은 별도 적용·검증이 필요하다.

## 경사 시험장·지면 감지 — 1단계

경사 시험은 **`Assets/TankPrototype/Scenes/TankAIIntegrationTest.unity`의 `Ground Probe Test`**에서 한다. 기존 평지 경로 시험 옆에 독립 Terrain을 추가했다. 맵 제작자가 사용하는 `TankTest` 씬은 이 작업에서 수정하지 않았다.

- Terrain 높이맵: 513×513, 크기 160×14×120m, 월드 위치 (-80, -1, 120). 5°·10°·15° 오르내리막은 중간에 일정 경사 구간을 두고 시작·끝을 부드럽게 연결했다. 옆경사 10°와 둔덕도 있다.
- `TigerTank`, `EnemyTank-Sherman` 원본 프리팹에 `TankGroundProbe`를 추가하고, 각 차체 BoxCollider 바닥에 맞춰 중앙·네 모서리 감지 위치를 저장했다.
- 씬의 두 `Probe Sample - parked`는 원본 전차의 메시와 차체 크기를 복사한 **감지 확인용 고정 샘플**이다. Rigidbody는 kinematic이며 모터·AI·네트워크 컴포넌트가 없다. 경사에 맞춰 놓인 자세는 시험 배치이며, 자동 자세 보정의 구현 결과가 아니다.
- 1단계 당시에는 감지까지만 적용했다. 공용 모터와 회전 잠금의 이후 변경은 아래 2단계에 정리한다. `TankAI`, `TankPath`, 기존 NavMesh는 그대로 유지한다.

### 직접 확인하기

1. `TankAIIntegrationTest`를 열고 Hierarchy에서 **`Ground Probe Test`**를 선택한다.
2. Inspector의 `Tank Ground Demo`에서 평지, 5°·10°·15°, 옆경사, 둔덕, 공중, 가장자리, 먼 지면 버튼을 선택한다. 편집 모드와 Play Mode 모두 사용할 수 있다.
3. **`View samples in Scene`**을 누르면 두 샘플 주변으로 화면이 이동하고 Tiger 샘플이 선택된다. Scene의 Gizmos를 켠다. Sherman은 같은 루트 아래에서 선택한다.
4. 각 샘플의 **`Tank Ground Probe → Ground reading`**에서 `Grounded`, `Contacts / hits`, `Supported slope`를 본다. `Show samples in Game camera`는 기존 관찰 카메라를 샘플 쪽으로 돌린다. Play Mode에서 누르면 종료 시 카메라가 원래 상태로 돌아간다.

| 조건 | 두 샘플의 Play Mode 확인 결과 |
| --- | --- |
| 평지 / 5° / 10° / 15° / 옆경사 / 둔덕 | 접지 YES, 접촉·감지 5/5. 일정 경사는 각각 0° / 5° / 10° / 15° / 10°로 측정 |
| 공중 3m | 접지 NO, 접촉·감지 0/0 |
| Terrain 가장자리 | 접지 YES, 접촉·감지 3/3. 나머지 두 감지점은 지면을 놓침 |
| 지면에서 0.6m 떨어짐 | 접지 NO, 접촉 0 / 감지 5. 아래 지면이 보인다는 이유로 접지 처리하지 않음 |

Gizmos 색은 **초록=접촉, 노랑=감지됐지만 접촉 범위 밖, 빨강=감지 없음, 하늘색=지지면 방향**이다. 접지가 해제되면 `Supported slope`는 마지막 접지 때의 값을 보관한다. 공중에서는 이 값을 유효한 지지면으로 사용하면 안 된다.

### 감지 기준과 검증 범위

Raycast는 월드 아래 방향으로 쏘고, 기본 `Ground Mask`는 `Default`다. 현재 정적 Terrain·도로 Collider를 감지하며 자기 계층, 모든 Rigidbody에 붙은 Collider(다른 전차 포함), 트리거는 제외한다. `InteriorDevice`, `TankInterior` 레이어는 기본 마스크 밖이다. 추후 도로·지형에 별도 레이어를 사용하면 프리팹의 마스크에도 추가한다. 네트워크 전차의 반복 감지는 유효한 `NetworkObject`의 StateAuthority에서만 수행하고, 네트워크가 없는 고정 샘플은 로컬에서 감지한다.

차체 바닥에서 -0.12~+0.2m 범위에 든 점을 접촉으로 보고 기본 2점 이상에서 접지로 판단한다. Raycast의 전체 감지 깊이(바닥 아래 1m)와 접촉 허용 거리를 구분한다. 유효한 지점들의 위치로 지지면을 구하고, 3점 미만만 남으면 기존 지지면 방향을 유지한다. 16개 결과 버퍼가 가득 차면 해당 점을 제외하고 Inspector에 경고한다.

Unity 6000.6.3f1 Play Mode에서 두 차체 × 9조건과 정적 도로·자기 차체·트리거·다른 Rigidbody·내부 레이어 필터를 확인했다. 워밍업 후 1,000회 감지 측정에서 추가 관리 메모리 할당은 0바이트였다. 로컬 검증 기록은 `Builds/TankGroundProbe/play-check.txt`에 있다. 이 수치는 해당 에디터에서의 감지 검사이며, Player 성능·실제 경사 주행·네트워크 검증을 대신하지 않는다.

TerrainData와 감지 샘플은 씬·에셋으로 저장되어 있다. 일회용 생성·검증 도구 없이 동작한다. 2단계도 이 Terrain과 공용 프리팹의 감지 정보를 사용한다.

## 공용 모터 지형 대응 — 2단계

`TigerTank`와 `EnemyTank-Sherman`의 공용 `TankMotor`에 경사 이동·차체 자세 보정·정지·공중 처리를 연결했다. 두 프리팹의 기존 지면 감지를 직렬화 참조로 연결하고 X·Z 회전 잠금을 해제했다. 추진·회전은 유효한 StateAuthority에서 처리하며, 게스트가 별도로 물리를 구동하지 않는다.

- 지면에 전진 방향을 투영해 오르내리막과 옆경사에서 이동한다. 중력의 지면 방향 성분을 상쇄하고 횡이동을 제어해 지원 경사에서 정지·재출발할 수 있다.
- 입력 중에는 모터의 가속 상태를 유지한다. 접촉 처리로 작은 출발 속도가 매번 사라져 가속하지 못하는 상황을 방지한다. 중립 입력의 이동 제동과 착지 직후는 실제 속도를 기준으로 한다. 선회는 모터의 회전 가감속을 적용한다.
- 지면 방향에 맞춘 자세 보정과 레버 선회를 하나의 `Rigidbody.MoveRotation`에 합친다. `Tilt Speed`는 보정 속도 상한, `Tilt Gain`은 기울기 오차에 대한 보정 세기다.
- `Stop()`은 지면 방향의 이동·선회를 중단하고, 이후 물리 틱의 자세 보정은 유지한다. 공중에서는 추진·회전·강제 접지 없이 기존 속도와 중력을 보존한다. 공중에서 `Stop()`을 호출해도 비행 속도를 지우지 않는다.
- 회전 방식에 맞춰 궤도 애니메이션과 기존 회전속도 진단은 실제 차체 회전 변화량을 읽는다. 기존 레버 입력·표시 API는 유지한다.

### 직접 운전하기

1. **`TankAIIntegrationTest`** 씬에서 **`Ground Drive Test`**를 선택하고 Play한다. `Ground Probe Test`는 기존 감지 확인용 고정 샘플이다.
2. Inspector의 **`Drive Tiger`** 또는 **`Drive Sherman`**을 누른다.
3. **`Reset: 01 Flat`**, **`02 Uphill 5 deg`**, **`03 Uphill 10 deg`**, **`04 Uphill 15 deg`**, **`05 Side slope 10 deg`**, **`06 Rounded hill`** 중 원하는 지형을 선택한다. 두 주행 샘플을 수평 자세로 다시 배치하므로 자동으로 기울기를 맞추는 동작도 볼 수 있다.
4. **`Enable keyboard control`**을 누르고 Game 화면을 클릭한다. **W/S 전진·후진, A/D 선회, Space 즉시 정지**, 키를 놓으면 일반 감속이다. W 또는 S와 A/D를 같이 누르면 이동하며 선회한다.
5. 경사 중간에서 정지·재출발하고, A/D로 방향을 돌려 내리막 전진·오르막 후진도 본다. `Can drive`, 속도, `Ground slope`를 확인한다. 구역·전차를 바꿀 때는 Inspector를 사용한다.

운전용 샘플은 원본 메시·차체 Collider·마찰·질량을 사용하며 실제 공용 모터와 감지를 실행한다. 승무원 입력과 네트워크를 붙이지 않은 로컬 물리 시험이며 포탑·무기·궤도 애니메이터를 갖춘 완성 전차는 아니다. 기존 평지 AI 시험은 별도로 계속 실행된다. 고정 감지 샘플의 Collider는 주행을 방해하지 않도록 비활성화했고 감지 자체는 유지한다.

### 검증과 다음 범위

Unity 6000.6.3f1의 실제 Play Mode에서 두 차체의 평지·5°·10°·15°·옆경사 10° 주행, 경사 중간 정지·재출발·제자리 선회, 둔덕 통과·안정화, 공중 입력·정지 명령의 관성 보존을 확인했다. 기존 호스트 AI의 평지 NavMesh 코너 경로도 `Arrived`로 끝났다. 내리막 전진·오르막 후진, 이동 선회·중립 감속과 Tiger 궤도 회전 반영도 확인했다. 예열 후 감지+모터 1,000회 호출은 관리 메모리 추가 할당 0바이트, 약 12~13ms였다. 이 측정 루프는 PhysX 시뮬레이션·렌더링을 포함하지 않으며 에디터 측정이다. 검증 기록은 `Builds/TankGroundMotor/play-check.txt`에 있다.

지원 확인 범위는 시험한 부드러운 지형의 **15° 이하**다. `Max Drive Slope` 기본값 20°는 추진 차단 설정이며 20° 주행을 검증했다는 뜻이 아니다. 큰 턱·급경사·차륜별 서스펜션은 이번 범위가 아니다. 높이맵의 급한 변화와 좁은 길은 실제 맵에서 다시 확인한다.

경사용 NavMesh 베이크, 경사에서 AI 도착·정체 판정 보완은 **3단계**다. 경사에서의 조준·명중·발사 위치와 호스트·게스트의 전체 차체 회전 표시는 **4단계** 검증으로 남는다. `TankTest` 씬 파일과 기존 NavMesh는 이번 작업에서 수정하지 않았다. 다만 두 공용 전차 프리팹과 모터 변경은 이를 사용하는 다른 씬에도 적용된다.

## TankTest에서 바로 시험하기

네트워크 담당자와 확인할 때는 `Assets/TankPrototype/Scenes/TankTest.unity`를 사용한다. 기존 3인 Fusion 세션을 사용하며, Game 화면과 PC 실행 파일 오른쪽 위에 시험 패널이 표시된다.

1. Play를 끄고 **TankTest** 씬을 연다. Hierarchy에 **Enemy AI Network Test**가 있어야 한다.
2. Play를 누른다. 기존 `SessionJoinInit`으로 접속하면 패널에 `HOST · 조작 가능` 또는 `CLIENT · 관찰 전용`이 표시된다.
3. 호스트가 **적 생성 / 초기화**를 누른다. Sherman 한 대와 고정 표적 하나가 네트워크 생성되고 각 클라이언트에 관찰 화면이 열린다. 생성 버튼을 누르기 전에는 시험 적을 자동 생성하지 않는다.
4. **사각 순찰 시작**을 누른다. 첫 지점에 생성된 적은 **2 → 3 → 4 → 1 → 2…** 순서로 반복한다.
5. **전체 정지**를 눌러 이동·공격이 멈추는지 확인한다. 코너 대기 중에 눌러도 이후 순찰이 재개되면 안 된다.
6. **지정 표적 공격**을 누른다. 순찰을 취소하고 고정 표적을 조준·장전·공격한다. 표적 HP가 0이면 `TargetDown`에서 멈춘다.
7. 다시 시험하려면 **적 생성 / 초기화**를 누른다. 기존 시험 적·표적과 그 적이 발사한 남은 포탄을 정리하고 새로 생성한다.

마우스가 내부 시점에 잠겨 있으면 **F8**로 외부 모드로 전환한 뒤 버튼을 누른다. 기존 외부 관찰 키 **F8 → F4**도 사용할 수 있다. 패널 제목을 누르면 접거나 펼칠 수 있다.

**예전에 만든 exe에는 변경 사항이 없다.** 현재 코드·씬·프리팹을 포함해 PC 빌드를 다시 만들고 모든 접속자에게 같은 버전을 전달한다.

| 버튼 | 동작 |
| --- | --- |
| 적 생성 / 초기화 | 호스트가 `Runner.Spawn`으로 시험 적 1대와 표적 1개 생성. 재실행 시 기존 시험 대상 교체 |
| 사각 순찰 시작 | 실제 차체가 목표의 XZ 반경 1m 안에 도착하면 정지하고 0.1초 뒤 다음 지점으로 이동 |
| 전체 정지 | 순찰 예약, AI 이동·조준·무기 요청 취소 |
| 지정 표적 공격 | 순찰을 취소하고 고정 시험 표적 공격 |
| 시험 구역 화면 보기 / 닫기 | 이 클라이언트의 관찰 화면을 켜거나 끔. 호스트 권한 없이 사용 가능 |

클라이언트의 명령 버튼은 비활성화된다. 호스트 여부는 조종수·포수·전차장 자리와 별개다. 시험 공격 대상은 별도로 생성한 고정 표적이다.

관찰 화면은 각 클라이언트가 자기 씬을 렌더링한다. 같은 적의 위치·회전을 비교하는 용도이며, 기존 플레이어 카메라는 바꾸지 않는다. 생성·초기화 시 자동으로 켜지고 순찰 지점 번호도 표시한다.

## 공용 기능과 하위 AI의 연결

사각 순찰과 공격 버튼은 실제 공용 AI 명령을 호출한다. 이후 FSM이 행동을 선택할 때도 같은 기능을 사용한다.

| 구분 | 구성과 책임 |
| --- | --- |
| 명령과 진행 상태 | `TankAI`: 목적지·표적 명령 접수, 이동·공격 제어, 호스트·생존 검사 |
| 경로 계산과 진행 지점 | `TankPath`: 전차용 NavMesh 경로 계산, 중간 지점 보관·전환, 경로 표시. 주행 입력은 `TankAI`만 전달 |
| 전차의 실제 행동 | `TankMotor`, `TankAim`, `TankGun`, `TankProjectile`, `TankHealth` |
| 이후 추가할 판단 | 표적 탐지, 정찰·추격·전투 상태 선택, 목적지와 표적 결정 |
| 시험 전용 | `TankAINetworkTest`의 버튼·사각 경로·시험 표적·관찰 카메라와 개별 Demo |

네트워크 담당자는 공용 전차 기능의 상태와 결과를 기준으로 동기화를 연결한다. 시험 UI에 이동·공격 기능을 다시 구현할 필요는 없다.

### 호스트 실행과 결과 공유

`TankAI.IsHost`는 네트워크 Spawn 완료, 실행 중인 서버 Runner, StateAuthority를 확인한다. AI 판단은 호스트의 `FixedUpdateNetwork()`에서 수행한다. `CanAct`는 모터·조준·무기·Health의 활성 상태와 생존 여부도 검사한다.

호스트 AI의 Rigidbody는 동적으로 유지하고 입력이 있을 때 모터가 깨운다. 게스트 Rigidbody는 kinematic으로 두며 AI 입력을 실행하지 않는다.

| 공유 대상 | 현재 경로 |
| --- | --- |
| 적 생성·제거 | `Runner.Spawn` / `Runner.Despawn` |
| 차체 위치·회전 | `NetworkTransform` |
| 포탑·포신 각도, 약실 상태, 발사 수 | 기존 Networked 값 |
| 포탄 생성·비행·제거 | 기존 `TankGun`·`TankProjectile` 네트워크 경로 |
| 시험 대상 참조·시험 상태 | `TankAINetworkTest`의 Networked 값 |
| HP 값·파괴 색상 | 호스트 처리만 연결됨. 게스트 전달은 HP·피탄 동기화 작업에서 추가 연결 필요 |

호스트 검사만으로 새 상태가 자동 동기화되지는 않는다. `TankAI.MoveStatus`, `Destination`, `AttackStatus`, 표적 참조는 호스트의 진행 상태다. 시험 패널은 이동·공격 상태를 별도 진단 값으로 복제하며, 클라이언트 AI를 실행해 계산하지 않는다.

### 호출 API

네트워크 Spawn 완료 후 호스트에서 호출한다. `bool` 반환값은 명령 접수 여부다. 도착·실제 발사·명중 여부는 진행 상태와 전차 상태로 확인한다.

| API | 동작 |
| --- | --- |
| `MoveTo(point)` | 월드 XZ 목적지로 이동. 기존 자동 공격 취소 |
| `SetMoveMode(mode)` | `Direct` 또는 `NavMesh` 선택. 방식 변경 시 기존 이동 취소. 호스트·생존 검사 적용 |
| `StopMove()` | 목적지 이동 취소와 주행 정지 |
| `SetDrive(left, right)` | 목적지 이동·자동 공격 취소 후 직접 레버 입력 저장. 각 값 -1~1 |
| `Attack(targetAimPoint)` | 이동을 멈추고 지정 표적을 조준·장전·반복 공격 |
| `StopAttack()` | 자동 공격과 대기 중 AI 무기 요청 취소 |
| `SetAim(turret, barrel)` | 자동 공격 취소 후 직접 조준 입력 저장. 각 값 -1~1 |
| `RequestWeapon(action)` | 자동 공격 취소 후 기존 무기 동작 요청 |
| `StopActions()` | 이동·공격·조준 입력·대기 중 무기 요청·잔여 주행 정리 |

유효하지 않은 좌표·권한 등의 요청은 기존 명령을 바꾸지 않는다. 유효한 경로 이동 요청을 접수한 뒤 길을 찾지 못한 경우에는 `true`를 반환하고 `MoveStatus=Failed`, `MoveFailure`에 사유를 남긴다. `true`는 도착 성공이 아니다. 경로 실패 시 직선 이동으로 전환하지 않는다.

`StopMove`와 `StopAttack`은 각각 해당 기능만 취소한다. 공격 취소로 이미 장전된 탄이나 발사된 포탄을 제거하지는 않는다. 무기 요청은 조준 반영 후 `AfterTick`에서 처리한다.

```csharp
// 호스트에서 목적지를 지정한다. 매 틱 다시 호출할 필요는 없다.
// NavMesh 사용 시 생성 후 한 번 설정한다. 기존 시험 호환을 위한 기본값은 Direct다.
enemyAI.SetMoveMode(TankAI.MoveMode.NavMesh);
bool accepted = enemyAI.MoveTo(new Vector3(10f, 0f, 15f));

// 이후 호스트의 판단 코드에서 진행 상태를 확인한다.
if (enemyAI.MoveStatus == TankAI.MoveState.Arrived)
    enemyAI.Attack(targetAimPoint);

// 상태 전환 또는 명령 취소
enemyAI.StopActions();
```

## 지정 지점 이동·정지

아래는 기본 `Direct` 방식이다. `MoveTo(point)`는 Y를 제외한 월드 XZ 좌표를 사용한다. 이동 중 새 명령을 받으면 목적지를 교체한다. 비호스트, 파괴된 전차, 작동할 수 없는 모터, 유효하지 않은 좌표는 요청을 거부한다. `NavMesh` 방식의 추가 규칙은 뒤의 공용 경로 이동 절을 따른다.

전차 정면과 목적지의 각도 차이로 좌우 레버를 계산한다. 방향 차이가 크면 제자리 회전하고, 방향이 맞을수록 전진 비중을 높인다. 목적지에 가까워지면 거리와 모터 감속 성능으로 속도를 제한한다. 정지 반경 절반과 한 틱의 이동량을 제동 여유로 남긴다.

반경 안에서는 레버를 중립으로 두어 감속한다. 실제 선속도·회전속도도 기준을 만족하면 `Arrived`로 전환하고 다음 명령까지 대기한다. 계산에는 실제 Rigidbody 위치·회전을 사용한다.

| MoveStatus | 의미 |
| --- | --- |
| `Idle` | 목적지 이동 대기·취소. 직접 레버 조작도 포함 |
| `Moving` | 목적지로 회전·이동·감속 중. NavMesh 재탐색 대기 여부는 IsRetrying으로 구분 |
| `Arrived` | 허용 거리와 속도 기준을 만족해 정지 확정 |
| `Failed` | 경로 없음·NavMesh 범위 밖·경로 컴포넌트 상실·정체 재시도 한도 소진 등의 실패. `MoveFailure` 확인 |

| TankAI Inspector 항목 | 기본값 | 의미 |
| --- | --- | --- |
| Stop Radius | 0.5m | 전차 루트 기준 도착 허용 거리 |
| Slow Distance | 3m | 거리에 따라 속도를 낮추는 범위 |
| Turn Angle | 45° | 전진 없이 회전하는 각도 기준 |
| Turn Gain | 2 | 각도 오차에 따른 회전 속도 비율 |
| Turn Tolerance | 1.5° | 미세 조향을 멈추는 범위 |
| Stop Speed | 0.05m/s | 도착 판정 시 선속도 상한 |
| Stop Turn Speed | 0.5°/s | 도착 판정 시 회전속도 상한 |

적 충돌체는 `TankFlatTestZeroFriction` 물리 재질을 사용한다. 속도를 직접 적용하는 평지용 모터가 지면 마찰과 경합하지 않도록 한 설정이다. `Direct`는 막힘 없는 평지에서 사용하고, 고정 장애물 우회에는 `NavMesh` 방식을 명시적으로 선택한다. 장애물에 막혀도 거리가 남아 있으면 도착으로 처리하지 않는다.

### 작은 잔여 속도로 출발하지 못하던 문제

2026-11-12 정체 로그에서 목표 회전 `-120°/s`, 실제 회전 약 `+0.1°/s`, 모터 적용 회전 `0°/s`를 확인했다. 기존 `TankMotor.Approach`는 반대 방향 속도가 조금이라도 남으면 제동만 했다. 작은 반대 속도가 다시 생기면 매번 0을 넣어 새 방향으로 출발하지 못했다.

공용 모터에서 **반대 방향 잔여 속도가 수평 0.05m/s, 회전 0.5°/s 이하면 정지로 보고 새 방향으로 가속**하도록 수정했다. 그보다 큰 속도에서 방향을 바꾸면 먼저 감속한다. 이 수정은 같은 `TankMotor`를 사용하는 전차에 적용된다.

동일한 잔여 회전을 넣은 회귀 검사에서 수정 전 정체를 재현했고, 수정 후 두 바퀴 순찰을 완료했다. 양방향 회전·전후진 출발과 큰 속도에서의 제동 검사도 통과했다. 실제 TankTest Play의 최종 확인은 별도로 남아 있다.

## 지정 표적 조준·공격

`Attack(Transform)`은 표적 자신 또는 자식 조준점을 받는다. 조준점은 활성 상태이며 자신이나 부모에 살아 있는 `TankHealth`가 있어야 한다. 자기 전차를 표적으로 삼을 수 없다. 새 명령은 이동을 멈추고 표적을 교체한다.

현재 표적 위치를 매 틱 읽어 제자리에서 조준한다. 자동 탐색·추격·이동 표적 선행 조준은 없다. 적 사망·비활성화, 표적 소실·파괴 시 후속 공격을 중단하며, 발사 요청 소비 시점에도 표적 생존을 다시 검사한다.

| AttackStatus | 의미 |
| --- | --- |
| `Idle` | 공격 명령 없음 또는 취소 |
| `Aiming` | 포탑·포신 조준 중 |
| `Reloading` | 약실 열기·삽입·닫기 또는 발사 후 회복 중 |
| `Attacking` | 조준·탄도 검사를 통과해 발사 요청 전달 |
| `Blocked` | 사거리·포신 각도·장애물·무기 설정 등으로 보류. `AttackBlockReason` 확인 |
| `TargetDown` | 지정 표적이 파괴되어 공격 종료 |

조준과 장전은 함께 진행하므로 조준 중에도 `Reloading`이 표시될 수 있다. `Attacking`은 요청 전달 상태다. 실제 발사는 `TankGun.ShotCount`, 약실과 처리 결과는 `State`·`LastWeaponResult`, 명중은 표적 `CurrentHP`로 확인한다.

탄도와 발사 과정은 다음과 같다.

1. 포탄 속도·중력·고정 물리 시간 간격·수명으로 낮은 탄도의 발사 방향을 계산한다. 기존 `TankBallisticStep`의 중력 우선 적분 방식에 맞춘다.
2. 차체를 기준으로 포탑 좌우·포신 상하 각도를 구하고 `TankAim`의 회전 속도·각도 제한을 지킨다. 기본 조준 허용 오차는 0.5°다.
3. 기존 `TankGun`의 `OpenEmpty → Insert → Close → Fire → Recovering` 경로를 사용한다. 초기 약실이 열려 있으면 `Insert`부터 시작한다.
4. 발사 전 `TankBallistics.Predict`로 포탄 구체 경로를 검사한다. 자기 Collider를 제외한 첫 충돌 대상이 지정 표적에 속할 때만 발사한다. 기본 검사 주기는 0.1초다.
5. 실제 포탄 생성·충돌·피해는 `TankGun`·`TankProjectile`·`TankHealth`가 처리한다. AI가 표적 HP를 직접 깎지 않는다.

적 프리팹의 탄도 예측 자동 화면 갱신은 꺼 두었다. 게스트가 AI용 탄도 예측을 반복 실행하지 않는다.

## HP와 파괴 시 행동 중단

기본 HP는 100, 기본 포탄 피해는 25다. 네 번 명중하면 `100 → 75 → 50 → 25 → 0`이 된다.

- `TankHealth`는 유한한 양수 피해만 받으며 HP를 0 아래로 내리지 않는다. 비활성 Health와 이미 파괴된 대상은 추가 피해·피격·파괴 횟수 증가를 거부한다. 잘못된 초기 MaxHP는 100으로 보정한다.
- NetworkObject가 있는 전차는 Spawn 완료, 실행 중인 서버 Runner, StateAuthority를 확인한 뒤 HP를 변경한다. NetworkObject 없는 기존 로컬 표적은 로컬 피해 처리를 유지한다.
- HP·피격 기록 확정 후 `Died`를 한 번 호출한다. `TankAI`가 구독하여 다음 AI 틱을 기다리지 않고 `StopActions()`를 실행한다. 비활성화 시 구독을 해제한다.
- 자기 전차가 파괴되면 이동·공격을 `Idle`로 정리하고 새 명령을 거부한다. `TankGun`도 AI 요청과 장전·발사·회복 처리를 중단하며 `CanFire`는 false가 된다.
- 표적이 먼저 파괴되면 공격자는 `TargetDown`에서 멈춘다.
- 파괴 시 수평 이동·회전을 멈추고 중력에 의한 낙하는 유지한다. 차체·Collider는 잔해로 남고 렌더러가 어두워진다.
- 이미 발사된 포탄은 계속 날아가며 피해를 줄 수 있다. 파괴 직후 마지막 명중이 생겨도 새 발사라고 판단하지 말고 `ShotCount` 증가 여부를 확인한다. 종료된 포탄은 피해를 다시 처리하지 않는다.

HP 값·파괴 색상의 게스트 공유는 별도 동기화 작업이다. 시험 패널에도 HP는 **호스트 화면에만** 적·표적 값을 표시한다.

## TankTest 시험 구성과 진단

씬 루트 **Enemy AI Network Test**의 `TankAINetworkTest`는 기존 `SessionJoinInit`을 명시적으로 참조하는 Scene NetworkObject다. Runner와 다른 루트이므로 DontDestroyOnLoad로 함께 이동하지 않는다.

UI 명령은 호스트에서 접수해 다음 `FixedUpdateNetwork`에서 실행한다. 적·표적 참조와 시험 상태를 복제하므로 늦게 접속한 클라이언트도 같은 대상을 식별할 수 있다. 적 파괴·세션 준비 해제 시 예약 명령과 순찰을 중단하고, 생성 실패 시 부분 생성 대상도 정리한다.

고정 표적 `TankAINetworkTestTarget.prefab`은 기존 `TankTarget`을 바탕으로 네트워크 생성·Transform 공유를 추가했다. 초기화 시 `TankProjectile.SourceGun`으로 해당 시험 적의 포탄만 정리한다. 플레이어와 다른 오브젝트·포탄은 유지한다.

기존 은신용 Sherman과 플레이어 배치는 유지하고 제어 루트·생성 위치·순찰 표시·관찰 카메라를 추가했다. 관찰 화면은 켜져 있을 때 전용 RenderTexture로 렌더링하며 AudioListener를 추가하지 않았다.

### 위치와 속도 설정

| 항목 | 월드 좌표 |
| --- | --- |
| 제어 루트 | `(41, 0, -41)` |
| 적 생성 | `(43, 0.15, -35)` |

| 고정 표적 생성 | `(47, 0, -13)` |

순찰은 한 변 12m다. 제어 루트 아래 `AI Spawn Point`, `Patrol Point 1~4`, `AI Target Spawn Point` Transform으로 위치를 바꾼다.

`Fast Test Movement`가 켜져 있으면 생성한 시험 적에만 이동 속도 6m/s, 이동 가속·감속 8·10, 회전 속도 120°/s, 회전 가속·감속 360을 적용한다. 원본 프리팹과 개별 시험 씬의 설정은 유지한다. 옵션을 끄면 프리팹 값을 사용한다.

### 표시 값과 정체 경고

패널은 시험 상태·지점·완주 횟수·적 ID·위치·포탑/포신 각도·발사 수를 표시한다. 호스트에는 목표 거리, 이동·회전의 명령값과 실제 속도, AI·구동 갱신 횟수, Kinematic 여부도 표시한다.

**갱신 횟수는 코드 실행 횟수다.** 이전의 ‘물리 틱’ 표기도 같은 뜻이며, 이동 거리나 충돌 횟수가 아니다. 방향 차이가 크면 제자리 회전하므로 수평 속도가 0이어도 회전이 진행 중이면 정상일 수 있다.

3초마다 위치와 방향을 확인한다. 10cm 이상 이동하거나 5° 이상 회전하면 진행으로 본다. 둘 다 바뀌지 않으면 다음 원인을 구분해 경고한다.

| 경고 | 확인할 부분 |
| --- | --- |
| AI 판단 갱신 중단 | `TankAI`의 호스트·활성 상태와 갱신 횟수 |
| 차체 구동 갱신 중단 | `TankMotor` 권한·활성 상태와 물리 갱신 |
| 이동 중 구동 입력 없음 | AI 입력과 모터 입력 전달 |
| 구동 명령은 있으나 차체 정지 | 목표·적용·실제 속도, Rigidbody 제약과 접촉 상태 |

움직임이 회복되면 다음 확인 시 경고를 해제한다. 정체 경고만으로 장애물 충돌을 확정하지 않는다. 이동 요청 거부 시에는 `Rigidbody is kinematic` 등 실제 거부 사유를 표시한다.

목표 전환은 `[AI PATROL]`, 정체 발생은 `[AI PATROL STALLED]` 로그로 기록한다. 정체 로그에는 목표 방향 차이, AI 좌우 입력, 모터 입력, 목표·적용·실제 속도, AI·구동 갱신 횟수, Kinematic·Rigidbody 제약이 포함된다. 같은 경고를 매 프레임 출력하지 않는다.

## 공용 경로 이동 연결 (2026-11-13)

`TankAI.MoveTo()`가 경로 계산과 중간 지점 추종을 연결한다. `TankPath`는 경로만 계산·보관하고, `TankAI`가 좌우 레버 입력을 결정하며, 기존 `TankMotor`가 Rigidbody를 움직인다. NavMeshAgent의 자동 이동은 사용하지 않는다.

공용 적 프리팹의 기본 이동 방식은 `Direct`다. NavMesh가 없는 기존 TankTest·개별 이동 시험을 유지하며, 통합 시험 씬에서 생성한 적만 `SetMoveMode(NavMesh)`로 전환한다. 나중에 실제 맵에 적용할 때도 생성 후 같은 API를 한 번 호출한다. 경로·이동 방식·실패 사유는 호스트의 상태이며 클라이언트가 길을 다시 계산하지 않는다.

### 주행 규칙과 조정값

| 항목 | 초기값·규칙 |
| --- | --- |
| 경로 탐색 | TankFlat Agent, 모든 NavMesh Area. 시작·목적지는 0.75m 이내에서만 NavMesh로 보정 |
| 중간 지점 반경 | 0.25m. 최종 도착 반경 0.5m와 구분 |
| 급한 모퉁이 | 경로 방향 변화 30° 이상이면 감속·정지 후 회전. 새 구간 방향과 3° 이내로 맞춘 뒤 전진 |
| 완만한 모퉁이 | 1.5m/s를 기준으로 감속하며 다음 지점으로 전환 |
| 최종 도착 | 보정된 최종 목적지까지 거리와 실제 선속도·회전속도를 확인해 Arrived |
| 경로 버퍼 | 64칸 재사용. 버퍼가 가득 차면 잘린 경로를 따라가지 않고 Failed |
| 경로 갱신 | 새로운 이동 명령과 제한된 정체 재시도 시 계산. 추종 중 매 프레임·틱 재탐색하지 않음 |

`Destination`은 요청 좌표이고, `TankPath.Goal`은 NavMesh 위로 보정된 목적지다. 취소·직접 레버 입력·공격 전환·파괴 시 경로와 모퉁이 회전·재탐색 대기를 해제한다. `Failed` 뒤 새 명령은 새 재시도 한도로 수행한다. 아래 실패·명령 변경 처리 단계에서 정체 감지와 제한된 재탐색을 연결했다. 후진 탈출과 동적 장애물의 NavMesh 반영은 추가 범위다.

### 직접 확인 순서

1. Play를 끄고 `TankAIIntegrationTest`를 다시 연다. 기존에 Play 중이었다면 반드시 종료 후 다시 실행한다.
2. Hierarchy에서 `Tank AI Integration Demo`를 선택하고 Play한다. 기본 02 ㄱ자 통로의 적과 관찰 화면이 열린다.
3. 적이 통로를 따라 돌고 최종 목적지에서 멈추는지 본다. Inspector의 이동 방식은 NavMesh, 이동 상태는 Moving → Arrived여야 한다.
4. Inspector의 `03 벽 우회`를 누른다. 적이 새로 생성되고 중앙 벽을 돌아 목적지에서 멈춰야 한다.
5. `01 직선 이동`, `04 이동 불가`, `05 직선 통로`도 확인한다. 04는 Failed와 `No complete path to destination` 표시가 정상이다.
6. 이동 중 `전체 중지`를 눌러 멈추는지 확인한다. 구역 버튼을 다시 누르면 새 적으로 다시 시험한다.
7. Scene 뷰의 Gizmos를 켜면 청록색 경로와 노란색 현재 목표 지점이 보인다. Inspector에는 목표 지점 번호와 전체 지점 수, 실패 사유도 표시된다.

실제 이동 후 공격을 연결해서 확인하려면 `01 이동 → 정지 → 공격 통합 시험` 버튼을 누른다. 01의 출발점에서 새 적을 생성하고 한 번의 경로 이동 명령을 준 뒤, 도착 시 지정 표적 공격으로 이어진다. 다른 구역에서는 기존 공격 표적까지 거리·시야가 확보되지 않을 수 있다.

검증: 실제 Unity/Fusion 참조를 사용한 런타임·Editor 컴파일과 Fusion 코드 생성 검사 통과. 엔진 서비스를 대체한 제어 시뮬레이션에서 경로 제어 15개 및 기존 이동·공격·HP·네트워크 패널 52개 검사 통과. 반복 제어의 관리 메모리 할당도 이 시뮬레이션에서 확인했다. 실제 NavMesh의 주행 궤적·벽 접촉·화면과 Player Profiler는 Play Mode에서 별도로 확인해야 한다. 자동 실행 환경의 Unity 제어·라이선스 연결 문제로 이번 작업에서 실제 Play Mode는 수행하지 못했다.

## 실패·명령 변경 처리 (2026-11-13)

NavMesh 이동 명령에 정체 감지와 제한된 재탐색을 추가했다. 기존 Direct 이동은 유지한다. 초기 경로 없음·범위 밖 목적지·경로 컴포넌트 상실은 즉시 Failed이며, 실제 주행 중 정체된 경우에만 대기 후 재시도한다.

### 정체 판정과 재시도

| 항목 | 기본값·처리 |
| --- | --- |
| Stall Timeout | 현재 경로 지점에 가까워지는 진전이 4초 동안 없으면 정체 |
| Progress Distance | 0.25m 개선을 진전으로 확인. 아주 낮은 이동 속도에서는 기준도 낮춰 오판 방지 |
| Turn Grace | 기본 8초 이상의 회전 여유. 최대 회전 속도·가속도에 따라 확대하며 실제 목표 각도 오차의 개선도 확인 |
| Retry Delay | 정지 후 0.5초 대기 |
| Retry Limit | 이동 명령 한 건당 재시도 2회. 최초 경로 계산을 포함하면 최대 3회 계산 |
| 한도 소진 | Failed, 재탐색 예약·경로 해제, 주행 정지. 실패 사유와 사용한 재시도 횟수 유지 |

입력값이나 Rigidbody 속도가 크다는 이유로 진행 중이라고 판단하지 않는다. 경로 지점까지의 최단 도달 거리를 갱신하는지 확인하므로, 작은 위치 진동이나 같은 자리에서 도는 움직임이 계속 타이머를 초기화하지 않는다. 우회 경로에서는 최종 목적지와 잠깐 멀어져도 현재 지점으로 진행하면 정상이다.

정체되면 `Moving`을 유지한 채 `IsRetrying=true`로 대기한다. 재탐색에 성공하면 같은 목적지와 같은 명령 번호로 주행을 재개한다. 재탐색이 실패하면 남은 한도 안에서 다시 기다리고, 한도가 소진되면 종료한다. 잠깐 움직이거나 새 경로를 계산했다고 재시도 횟수를 0으로 되돌리지 않는다.

05 시험 장애물은 물리 충돌체만 켜고 NavMesh는 변경하지 않는다. 따라서 켜 둔 채로는 같은 길이 다시 계산될 수 있으며 두 차례 재시도 후 실패하는 것이 정상이다. 장애물이 사라지면 이동할 수 있지만, 실패가 확정된 뒤에는 자동으로 이전 명령을 되살리지 않고 새 이동 명령을 받아야 한다.

### 명령 변경과 예약 정리

| 상황 | 결과 |
| --- | --- |
| 대기 중 새 MoveTo | 이전 예약 폐기, 새 목적지로 계산, 재시도 횟수 초기화 |
| 잘못된 좌표·권한의 요청 | 현재 명령과 대기 예약 유지 |
| StopMove / StopActions | 이동·회전·재탐색 예약 해제, Idle |
| 직접 레버 입력 / 이동 방식 변경 | 기존 경로와 예약 해제 |
| Attack | 이동과 예약을 정리한 뒤 공격 명령 수행 |
| 파괴 / 컴포넌트 비활성화 | 예약과 입력 해제. 다시 활성화해도 이전 이동을 재개하지 않음 |

`CommandId`는 유효한 외부 행동 요청·중지에 따라 바뀌는 호스트의 명령 번호다. 시험 Demo의 ‘이동 후 공격’은 해당 이동의 번호와 일치할 때만 실행한다. 다른 이동·수동 조준·공격 중지 등으로 명령이 바뀌면 이전 도착 예약이 나중에 공격을 다시 시작하지 않는다. 내부 재시도는 번호를 바꾸지 않아, 허용된 이동 후 공격 흐름은 회복 이후에도 이어진다.

### 직접 확인 순서

Play를 종료하고 `TankAIIntegrationTest`를 다시 연 뒤 `Tank AI Integration Demo`를 선택해 Play한다. Inspector에서 이동 상태, 재탐색 대기, 재시도 횟수·한도, 진전 없는 시간, 최근 재시도 원인과 최종 실패 사유를 함께 확인한다.

| 확인 | 조작 | 기대 결과 |
| --- | --- | --- |
| 한도 소진 | `05 정체 유발 (장애물 포함)` | 벽에 막힌 뒤 대기·재시도 1 → 2 → Failed. 더 이상 벽을 밀지 않음 |
| 대기 중 회복 | 05 정체 시험을 다시 시작하고 첫 재탐색 대기 중 `장애물 끄기` | 같은 목적지로 다시 이동하여 Arrived |
| 실패 후 새 명령 | Failed 상태에서 `장애물 끄기` 후 `현재 목적지로 재명령` | 같은 적이 새 한도로 이동, Arrived |
| 목적지 변경 | 대기 중 장애물을 끄고 `출발 지점으로 재명령` | 새 목적지로 이동. 예전 목적지의 예약이 재개되지 않음 |
| 취소 | 재탐색 대기 중 `전체 중지` | Idle로 멈추고 기다려도 다시 이동하지 않음 |
| 파괴 | 재탐색 대기 중 `적 전차 파괴` | 이동·무기·재탐색 중단 |
| 경로 없음 | `04 이동 불가` | 재시도 없이 Failed, No complete path to destination |

구역 선택 버튼은 적을 새로 생성하지만, 재명령 버튼은 같은 적에 명령만 다시 전달한다. 다른 구역 시험을 시작하면 정체 장애물은 기본 비활성으로 돌아간다.

검증: 실제 Unity/Fusion 참조를 사용한 런타임·Editor 컴파일 및 Fusion 코드 생성 검사, 씬·프리팹 참조와 기존 브랜치 보존 검사. 제어 시뮬레이션에서는 실패·명령 변경 22개와 기존 67개, 총 89개 검사를 통과했다. 시뮬레이션은 실제 TankAI·TankPath·TankMotor·TankAttackDemo를 실행하고 엔진의 탐색·충돌·네트워크 서비스를 대체한다. 실제 충돌과 화면·Profiler 확인은 별도 Play Mode 검증으로 남긴다. 보고서는 `Builds/TankMoveRecovery/`에 저장한다.

## 통합 확인·정리 (2026-11-13)

공용 이동·정체 처리와 기존 조준·장전·발사·HP를 같은 시험 흐름으로 확인하고, 시험 Demo의 초기화와 안내를 보완했다.

- `01 이동 → 정지 → 공격 통합 시험`: 새 적으로 경로 이동을 시작하고 최종 도착 후 공격을 예약한다. 이동 중에는 발사하지 않으며, 도착한 뒤 기존 무기·피해 처리를 사용한다.
- 구역 초기화: 이전 시험 적이 발사한 남은 포탄만 해당 Runner·StateAuthority·SourceGun으로 식별해 제거한다. 다른 전차의 포탄과 시험 표적은 유지한다.
- 경로 요청이 접수됐어도 즉시 Failed인 경우 ‘이동 후 공격’을 예약하지 않는다. 적 생성에 실패해도 구역 버튼으로 다시 생성할 수 있다.
- 고정 공격 표적이 이미 파괴됐으면 통합 버튼을 비활성화한다. 재시험은 Play를 종료하고 다시 시작한다.

### 새 통합 버튼의 실제 확인

1. Play를 종료하고 `TankAIIntegrationTest`를 연 뒤 `Tank AI Integration Demo`를 선택해 Play한다.
2. Inspector의 `01 이동 → 정지 → 공격 통합 시험`을 누른다.
3. 01 목적지까지 이동하고 정지한 뒤 포탑·포신 조준과 장전·발사가 시작되는지 확인한다. 이동 상태는 `Moving → Arrived → Idle`로 바뀌며, 공격 중 Idle은 정상이다.
4. Inspector의 실제 발사 수와 표적 HP가 `100 → 75 → 50 → 25 → 0`으로 바뀌고, 공격 상태가 `TargetDown`으로 끝나는지 본다.
5. 표적을 파괴하기 전에 구역을 바꾸면 이전 적과 그 적의 남은 포탄이 정리되는지 확인한다. 표적 HP는 구역을 바꿔도 복구되지 않는다.

## 기능별 개별 시험 씬

다음 씬은 로컬 Fusion Single 세션을 만드는 개발용 시험이다. 3인 동기화 확인은 TankTest에서 별도로 진행한다. 실행 전에 Play를 끄고 원하는 씬을 열어 Hierarchy 상단의 씬 이름을 확인한다.

| 씬 경로: `Assets/TankPrototype/Scenes/` | 용도 | 선택할 조작 오브젝트 |
| --- | --- | --- |
| `TankMoveTest.unity` | 목적지 이동·정지 | Tank Move Demo |
| `TankAttackTest.unity` | 지정 표적 조준·공격 | Tank Attack Demo |
| `TankAIIntegrationTest.unity` | NavMesh 경로 이동 구역 시험, 선택적으로 이동 후 공격·HP 중단 확인 | Tank AI Integration Demo |

Demo와 NetworkRunner는 서로 다른 루트다. Runner는 실행 중 DontDestroyOnLoad로 이동할 수 있고 조작용 Demo는 원래 씬에 남는다. 예전 구성으로 실행 중이면 Play를 종료하고 현재 씬을 다시 연다.

### 이동만 확인하기

1. TankMoveTest에서 Play를 누르면 적 한 대가 Spawn Point에서 Destination으로 이동한다. 기본 목적지는 `(0, 0.03, 8)`이다.
2. 감속·정지 후 Console의 `[AI MOVE] Arrived and stopped.`를 확인한다.
3. Play 중 Destination을 옮기고 Tank Move Demo의 `TankMoveDemo` 컴포넌트 메뉴에서 **Move To Goal**을 실행하면 새 목적지로 이동한다.
4. **Stop Movement**로 이동 취소를 확인한다.

Destination을 옮기는 것만으로 명령이 바뀌지는 않는다. Move To Goal 실행 시 위치를 목적지로 복사한다.

### 공격만 확인하기

1. TankAttackTest에서 Play를 누르면 적이 Attack Target을 조준·장전·공격한다.
2. Hierarchy의 **Tank Attack Demo**를 선택해 Inspector의 상태·약실·실제 발사 수·표적 HP를 본다.
3. 약 10초 관찰하며 표적 HP가 `100 → 75 → 50 → 25 → 0`으로 감소하고, `TargetDown` 이후 추가 발사가 멈추는지 확인한다.
4. **공격 중지 (Stop Attack)**로 취소하고 **지정 표적 공격 (Attack Target)**으로 살아 있는 표적을 재지정한다. 파괴된 표적은 Play 재시작으로 초기화한다.

성공 기준은 발사 로그뿐 아니라 실제 명중 후 HP 감소다. Console의 `Tank fire: Fired #…`, `HP … -> …`, `[AI ATTACK] TargetDown`도 함께 확인한다.

표적은 기존 TankTarget을 바탕으로 구성했다. 자식 Aim Point의 위치 `(0, 1.3, -0.85)`로 피격 가능한 포탑 부분을 겨냥한다.

| 추가 시험 | 조작 | 기대 결과 |
| --- | --- | --- |
| 위치 변경 | Play 중 Attack Target 루트 이동. Aim Point는 표적 안에 유지 | 현재 위치 재조준. 이동 속도를 예측하는 선행 조준은 없음 |
| 가림 | 예: 위치 `(3, 2, 7)`, 크기 `(4, 4, 1)`의 Collider 있는 Cube 배치 | `Blocked / Shot path obstructed`; 벽 제거 후 재개 |
| 사거리 초과 | 표적을 `(0, 0, 100)`으로 이동 | `Blocked / Target outside ballistic range` |
| 표적 비활성화 | Attack Target 비활성화 | `Idle / Target unavailable`; 다시 켠 뒤 공격 버튼으로 재지정 |

**이동 후 공격**, **지정 표적 공격**으로 살아 있는 전차에 재명령할 수 있다. **전체 중지**는 이동과 공격 예약을 함께 취소한다. 전체 상태 초기화는 Play를 다시 시작한다.

## 네트워크 담당자 확인 순서

세 명이 같은 빌드와 TankTest 세션을 사용한다. 호스트만 명령하고 각 화면에서 같은 적 ID·동작을 확인한다.

| 순서 | 호스트 조작 | 각 화면에서 확인 |
| --- | --- | --- |
| 1 | 세 명 접속 후 적 생성 | 적·표적이 하나씩 보이고 적 ID가 동일함 |
| 2 | 사각 순찰 두 바퀴 이상 | 이동·회전·코너 정지가 전달되고 원격 AI가 별도로 실행되지 않음 |
| 3 | 이동 중 및 코너 대기 중 전체 정지 | 모든 화면에서 정지하고 뒤늦게 재출발하지 않음 |
| 4 | 지정 표적 공격 | 포탑·포신 방향, 포탄, 발사 수 전달. 호스트에서 표적 HP 감소 |
| 5 | 포탄 비행 중 초기화 | 새 적·표적으로 교체되고 이전 시험 포탄이 새 표적을 때리지 않음 |
| 6 | 순찰 진행 중 나머지 클라이언트 접속 | 기존 적을 중복 생성하지 않고 같은 진행 상태 관찰 |

전송과 보간 때문에 매 프레임 위치 수치가 완전히 같을 필요는 없다. 같은 경로로 움직이고 정지 후 위치가 수렴하는지 확인한다. 현재 클라이언트 비교 범위는 생성·제거, 차체·조준 회전, 포탄·발사 수, 정지 결과다. HP·파괴 색상 공유는 추가 연결 후 확인한다.

## 검증 결과와 남은 작업

런타임·Editor C# 컴파일과 Fusion ILPostProcessor를 통한 코드 생성을 검사했다. 런타임 컴파일에는 기존 경고 2건이 남아 있다. 마지막 모터 수정 후 런타임 컴파일·코드 생성·회귀 검사를 통과했다.

최신 로직 검사는 `Builds/TankPathIntegration`에서 실제 시험 Demo·AI·모터·경로·조준·무기·HP·탄도 계산 소스를 함께 실행한다. 새 연결 통합 7개, 실패·명령 변경 22개, 경로 추종 15개, 기존 패널 17개·공격 10개·HP 9개·이동 16개로 총 96개 검사 그룹을 통과했다.

주요 검사는 다음을 포함한다.

- 네 지점의 정확한 순서와 두 바퀴 순찰, 코너 대기 중 취소, 잘못된 도착 플래그, 시험 대상 초기화·부분 생성 실패·세션 준비 해제 정리.
- 기록된 반대 방향 잔여 회전에서의 출발, 좌우 회전·전후진, 큰 속도에서의 제동, 다른 AI·물리 갱신 주기, 예열 후 이동 루프의 관리 메모리 할당.
- 탄도 계산·조준 수렴·장전·반복 발사, 장애물·사거리·포신 각도에 따른 보류와 재개, 취소·표적 소실·파괴·호스트 제한.
- 네 번의 25 피해와 파괴 이벤트 한 번, 잘못된 피해 거부, 이동·공격 중 자기 파괴 즉시 중단, 파괴 후 명령 거부.
- 실제 Demo의 NavMesh 이동 후 공격 예약 → 기존 무기 요청 → 네 번의 모형 명중 → TargetDown, 정체 회복 이후 같은 연결, 취소·실패 뒤 예약이 재개되지 않는 흐름.
- 개별 시험 초기화 시 해당 적의 포탄만 제거하고 다른 전차·다른 Runner·비권한 포탄을 유지하는 흐름, 부분 생성 실패 후 다시 생성.

**로직 검사는 엔진·Fusion 서비스와 충돌을 대체 객체로 실행했다.** 시험 포탄의 피해를 Health에 전달하는 방식으로 명중을 모형화했다. 네이티브 PhysX 접촉이나 실제 Fusion 통신을 통과했다는 뜻은 아니다. 앞선 동작에 대한 사용자 확인과 자동 검사 결과를 구분한다. 새 통합 버튼의 실제 발사·접촉, 실제 TankTest의 지형 접촉·패널 배치와 3인 접속·늦은 접속은 별도로 확인한다.

| 로컬 기록 위치 | 내용 |
| --- | --- |
| `Builds/TankPathIntegration/logic-results.txt` | 최신 이동·공격 연결 통합 및 기존 96개 회귀 검사 |
| `Builds/TankPathIntegration/weaver-results.txt` | 최신 Fusion 코드 생성 검사 |

Builds의 검사·백업은 로컬 산출물이며 팀원이 저장소에서 받는 공용 런타임 코드와 구분한다. 초기 문서의 ‘TankTest 변경 없음’ 기록은 프리팹 구성 당시의 범위다. 현재는 기존 배치를 유지하면서 네트워크 시험 루트를 추가한 상태다.

남은 개발은 표적 탐지·목격 정보·상황 판단·FSM·임무 복귀 연결, 실제 맵 적용과 주행 검증, HP·피탄 결과 동기화와 실제 다중 접속 확인이다. 이후 판단 계층은 이번 공용 경로 이동·공격 API를 재사용한다.
