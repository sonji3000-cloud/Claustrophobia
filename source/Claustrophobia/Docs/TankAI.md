# 적 전차 AI 개발·시험 가이드

기준일: 2026-11-12. 적 프리팹 구성, 호스트 실행, 지정 지점 이동, 지정 표적 공격, HP·파괴 중단, TankTest 시험 방법을 한곳에 정리한다.

현재 공용 기능은 **지정 지점으로 이동·정지하고, 지정 표적을 조준·장전·반복 공격하며, 파괴되면 행동을 중단하는 것**이다. 이후 하위 AI는 상황을 판단해 같은 명령을 호출하도록 확장한다. 자동 표적 탐지, 추격 판단, 장애물 경로 탐색, 상세 FSM은 아직 구현하지 않았다.

## TankTest에서 바로 시험하기

네트워크 담당자와 확인할 때는 `Assets/TankPrototype/Scenes/TankTest.unity`를 사용한다. 기존 3인 Fusion 세션을 사용하며, Game 화면과 PC 실행 파일 오른쪽 위에 시험 패널이 표시된다.

1. Play를 끄고 **TankTest** 씬을 연다. Hierarchy에 **Enemy AI Network Test**가 있어야 한다.
2. Play를 누른다. 기존 `SessionJoinInit`으로 접속하면 패널에 `HOST · 조작 가능` 또는 `CLIENT · 관찰 전용`이 표시된다.
3. 호스트가 **적 생성 / 초기화**를 누른다. Sherman 한 대와 고정 표적 하나가 네트워크 생성되고 각 클라이언트에 관찰 화면이 열린다. 생성 버튼을 누르기 전에는 시험 적을 자동 생성하지 않는다.
4. **사각 순찰 시작**을 누른다. 첫 지점에 생성된 적은 **2 → 3 → 4 → 1 → 2…** 순서로 반복한다.
5. **전체 정지**를 눌러 이동·공격이 멈추는지 확인한다. 코너 대기 중에 눌러도 이후 순찰이 재개되면 안 된다.
6. **지정 표적 공격**을 누른다. 순찰을 취소하고 고정 표적을 조준·장전·공격한다. 표적 HP가 0이면 `TargetDown`에서 멈춘다.
7. 다시 시험하려면 **적 생성 / 초기화**를 누른다. 기존 시험 적·표적과 그 적이 발사한 남은 포탄을 정리하고 새로 생성한다.

마우스가 내부 시점에 잠겨 있으면 **F8**로 외부 모드로 전환한 뒤 버튼을 누른다. 기존 외부 관찰 키 **F8 → F4**도 사용할 수 있다. 패널 제목을 누르면 접거나 펼칠 수 있다.

**예전에 만든 exe에는 변경 사항이 없다.** 현재 코드·씬·프리팹을 포함해 PC 빌드를 다시 만들고 모든 접속자에게 같은 버전을 전달한다.

| 버튼 | 동작 |
| --- | --- |
| 적 생성 / 초기화 | 호스트가 `Runner.Spawn`으로 시험 적 1대와 표적 1개 생성. 재실행 시 기존 시험 대상 교체 |
| 사각 순찰 시작 | 실제 차체가 목표의 XZ 반경 1m 안에 도착하면 정지하고 0.1초 뒤 다음 지점으로 이동 |
| 전체 정지 | 순찰 예약, AI 이동·조준·무기 요청 취소 |
| 지정 표적 공격 | 순찰을 취소하고 고정 시험 표적 공격 |
| 시험 구역 화면 보기 / 닫기 | 이 클라이언트의 관찰 화면을 켜거나 끔. 호스트 권한 없이 사용 가능 |

클라이언트의 명령 버튼은 비활성화된다. 호스트 여부는 조종수·포수·전차장 자리와 별개다. 시험 공격 대상은 별도로 생성한 고정 표적이다.

관찰 화면은 각 클라이언트가 자기 씬을 렌더링한다. 같은 적의 위치·회전을 비교하는 용도이며, 기존 플레이어 카메라는 바꾸지 않는다. 생성·초기화 시 자동으로 켜지고 순찰 지점 번호도 표시한다.

## 공용 기능과 하위 AI의 연결

사각 순찰과 공격 버튼은 실제 공용 AI 명령을 호출한다. 이후 FSM이 행동을 선택할 때도 같은 기능을 사용한다.

| 구분 | 구성과 책임 |
| --- | --- |
| 명령과 진행 상태 | `TankAI`: 목적지·표적 명령 접수, 이동·공격 제어, 호스트·생존 검사 |
| 전차의 실제 행동 | `TankMotor`, `TankAim`, `TankGun`, `TankProjectile`, `TankHealth` |
| 이후 추가할 판단 | 표적 탐지, 정찰·추격·전투 상태 선택, 목적지와 표적 결정 |
| 시험 전용 | `TankAINetworkTest`의 버튼·사각 경로·시험 표적·관찰 카메라와 개별 Demo |

네트워크 담당자는 공용 전차 기능의 상태와 결과를 기준으로 동기화를 연결한다. 시험 UI에 이동·공격 기능을 다시 구현할 필요는 없다.

### 호스트 실행과 결과 공유

`TankAI.IsHost`는 네트워크 Spawn 완료, 실행 중인 서버 Runner, StateAuthority를 확인한다. AI 판단은 호스트의 `FixedUpdateNetwork()`에서 수행한다. `CanAct`는 모터·조준·무기·Health의 활성 상태와 생존 여부도 검사한다.

호스트 AI의 Rigidbody는 동적으로 유지하고 입력이 있을 때 모터가 깨운다. 게스트 Rigidbody는 kinematic으로 두며 AI 입력을 실행하지 않는다.

| 공유 대상 | 현재 경로 |
| --- | --- |
| 적 생성·제거 | `Runner.Spawn` / `Runner.Despawn` |
| 차체 위치·회전 | `NetworkTransform` |
| 포탑·포신 각도, 약실 상태, 발사 수 | 기존 Networked 값 |
| 포탄 생성·비행·제거 | 기존 `TankGun`·`TankProjectile` 네트워크 경로 |
| 시험 대상 참조·시험 상태 | `TankAINetworkTest`의 Networked 값 |
| HP 값·파괴 색상 | 호스트 처리만 연결됨. 게스트 전달은 HP·피탄 동기화 작업에서 추가 연결 필요 |

호스트 검사만으로 새 상태가 자동 동기화되지는 않는다. `TankAI.MoveStatus`, `Destination`, `AttackStatus`, 표적 참조는 호스트의 진행 상태다. 시험 패널은 이동·공격 상태를 별도 진단 값으로 복제하며, 클라이언트 AI를 실행해 계산하지 않는다.

### 호출 API

네트워크 Spawn 완료 후 호스트에서 호출한다. `bool` 반환값은 명령 접수 여부다. 도착·실제 발사·명중 여부는 진행 상태와 전차 상태로 확인한다.

| API | 동작 |
| --- | --- |
| `MoveTo(point)` | 월드 XZ 목적지로 이동. 기존 자동 공격 취소 |
| `StopMove()` | 목적지 이동 취소와 주행 정지 |
| `SetDrive(left, right)` | 목적지 이동·자동 공격 취소 후 직접 레버 입력 저장. 각 값 -1~1 |
| `Attack(targetAimPoint)` | 이동을 멈추고 지정 표적을 조준·장전·반복 공격 |
| `StopAttack()` | 자동 공격과 대기 중 AI 무기 요청 취소 |
| `SetAim(turret, barrel)` | 자동 공격 취소 후 직접 조준 입력 저장. 각 값 -1~1 |
| `RequestWeapon(action)` | 자동 공격 취소 후 기존 무기 동작 요청 |
| `StopActions()` | 이동·공격·조준 입력·대기 중 무기 요청·잔여 주행 정리 |

유효하지 않은 요청은 기존 명령을 바꾸지 않는다. `StopMove`와 `StopAttack`은 각각 해당 기능만 취소한다. 공격 취소로 이미 장전된 탄이나 발사된 포탄을 제거하지는 않는다. 무기 요청은 조준 반영 후 `AfterTick`에서 처리한다.

```csharp
// 호스트에서 목적지를 지정한다. 매 틱 다시 호출할 필요는 없다.
bool accepted = enemyAI.MoveTo(new Vector3(10f, 0f, 15f));

// 이후 호스트의 판단 코드에서 진행 상태를 확인한다.
if (enemyAI.MoveStatus == TankAI.MoveState.Arrived)
    enemyAI.Attack(targetAimPoint);

// 상태 전환 또는 명령 취소
enemyAI.StopActions();
```

## 적 프리팹 구성

- 적 프리팹: `Assets/TankPrototype/Prefabs/EnemyTank-Sherman.prefab`.
- 원본 모델: `Assets/polyperfect/Low Poly War Pack/- Meshes/- Vehicles/Tank-Sherman.fbx`.
- 몸체·궤도는 원본 모델을 참조하는 `Model` 인스턴스다. 포탑·포신은 같은 FBX의 메시·재질을 쓰는 별도 조준축이다. `Model`에서 중복 포탑·포신과 기존 Animator를 제외했다.
- 모델·재질 원본과 기존 적 프리팹 GUID는 유지했다. 전차 기능 컴포넌트와 내부 참조를 프리팹에 저장했다.
- `TankTest`에 원래 배치된 Sherman들은 은신용으로 유지한다. AI 시험에서는 별도 적 프리팹을 동적으로 생성한다.

| 구성 | 역할 |
| --- | --- |
| `Rigidbody` + BoxCollider 3개 | 차체·궤도 범위, 포탑, 포신의 물리 구성 |
| `NetworkObject`, `NetworkTransform` | 네트워크 등록과 차체 결과 공유 |
| `TankMotor` | 좌우 레버 이동·회전 |
| `TankAim` | 포탑·포신 조준과 각도 상태 |
| `TankGun`, `TankProjectile` | 약실·발사·포탄 생성·충돌 |
| `TankHealth` | HP·피해·파괴 판정 |
| `TankAI` | 호스트 검사와 공용 전차 기능 호출 |

플레이어용 `TankInput`, `TankControl`, `TankCrewRegistry`, 카메라·내부 씬 연결은 적 프리팹에 넣지 않는다. 초기 상태는 입력 0인 대기 상태이며, 스스로 목적지나 표적을 선택하지 않는다.

## 지정 지점 이동·정지

`MoveTo(point)`는 Y를 제외한 월드 XZ 좌표를 사용한다. 이동 중 새 명령을 받으면 목적지를 교체한다. 비호스트, 파괴된 전차, 작동할 수 없는 모터, 유효하지 않은 좌표는 요청을 거부한다.

전차 정면과 목적지의 각도 차이로 좌우 레버를 계산한다. 방향 차이가 크면 제자리 회전하고, 방향이 맞을수록 전진 비중을 높인다. 목적지에 가까워지면 거리와 모터 감속 성능으로 속도를 제한한다. 정지 반경 절반과 한 틱의 이동량을 제동 여유로 남긴다.

반경 안에서는 레버를 중립으로 두어 감속한다. 실제 선속도·회전속도도 기준을 만족하면 `Arrived`로 전환하고 다음 명령까지 대기한다. 계산에는 실제 Rigidbody 위치·회전을 사용한다.

| MoveStatus | 의미 |
| --- | --- |
| `Idle` | 목적지 이동 대기·취소. 직접 레버 조작도 포함 |
| `Moving` | 목적지로 회전·이동·감속 중 |
| `Arrived` | 허용 거리와 속도 기준을 만족해 정지 확정 |

| TankAI Inspector 항목 | 기본값 | 의미 |
| --- | --- | --- |
| Stop Radius | 0.5m | 전차 루트 기준 도착 허용 거리 |
| Slow Distance | 3m | 거리에 따라 속도를 낮추는 범위 |
| Turn Angle | 45° | 전진 없이 회전하는 각도 기준 |
| Turn Gain | 2 | 각도 오차에 따른 회전 속도 비율 |
| Turn Tolerance | 1.5° | 미세 조향을 멈추는 범위 |
| Stop Speed | 0.05m/s | 도착 판정 시 선속도 상한 |
| Stop Turn Speed | 0.5°/s | 도착 판정 시 회전속도 상한 |

적 충돌체는 `TankFlatTestZeroFriction` 물리 재질을 사용한다. 속도를 직접 적용하는 평지용 모터가 지면 마찰과 경합하지 않도록 한 설정이다. 장애물 우회는 아직 없으므로 막힘 없이 이동할 수 있는 평지에서 시험한다. 장애물에 막혀도 거리가 남아 있으면 도착으로 처리하지 않는다.

### 작은 잔여 속도로 출발하지 못하던 문제

2026-11-12 정체 로그에서 목표 회전 `-120°/s`, 실제 회전 약 `+0.1°/s`, 모터 적용 회전 `0°/s`를 확인했다. 기존 `TankMotor.Approach`는 반대 방향 속도가 조금이라도 남으면 제동만 했다. 작은 반대 속도가 다시 생기면 매번 0을 넣어 새 방향으로 출발하지 못했다.

공용 모터에서 **반대 방향 잔여 속도가 수평 0.05m/s, 회전 0.5°/s 이하면 정지로 보고 새 방향으로 가속**하도록 수정했다. 그보다 큰 속도에서 방향을 바꾸면 먼저 감속한다. 이 수정은 같은 `TankMotor`를 사용하는 전차에 적용된다.

동일한 잔여 회전을 넣은 회귀 검사에서 수정 전 정체를 재현했고, 수정 후 두 바퀴 순찰을 완료했다. 양방향 회전·전후진 출발과 큰 속도에서의 제동 검사도 통과했다. 실제 TankTest Play의 최종 확인은 별도로 남아 있다.

## 지정 표적 조준·공격

`Attack(Transform)`은 표적 자신 또는 자식 조준점을 받는다. 조준점은 활성 상태이며 자신이나 부모에 살아 있는 `TankHealth`가 있어야 한다. 자기 전차를 표적으로 삼을 수 없다. 새 명령은 이동을 멈추고 표적을 교체한다.

현재 표적 위치를 매 틱 읽어 제자리에서 조준한다. 자동 탐색·추격·이동 표적 선행 조준은 없다. 적 사망·비활성화, 표적 소실·파괴 시 후속 공격을 중단하며, 발사 요청 소비 시점에도 표적 생존을 다시 검사한다.

| AttackStatus | 의미 |
| --- | --- |
| `Idle` | 공격 명령 없음 또는 취소 |
| `Aiming` | 포탑·포신 조준 중 |
| `Reloading` | 약실 열기·삽입·닫기 또는 발사 후 회복 중 |
| `Attacking` | 조준·탄도 검사를 통과해 발사 요청 전달 |
| `Blocked` | 사거리·포신 각도·장애물·무기 설정 등으로 보류. `AttackBlockReason` 확인 |
| `TargetDown` | 지정 표적이 파괴되어 공격 종료 |

조준과 장전은 함께 진행하므로 조준 중에도 `Reloading`이 표시될 수 있다. `Attacking`은 요청 전달 상태다. 실제 발사는 `TankGun.ShotCount`, 약실과 처리 결과는 `State`·`LastWeaponResult`, 명중은 표적 `CurrentHP`로 확인한다.

탄도와 발사 과정은 다음과 같다.

1. 포탄 속도·중력·고정 물리 시간 간격·수명으로 낮은 탄도의 발사 방향을 계산한다. 기존 `TankBallisticStep`의 중력 우선 적분 방식에 맞춘다.
2. 차체를 기준으로 포탑 좌우·포신 상하 각도를 구하고 `TankAim`의 회전 속도·각도 제한을 지킨다. 기본 조준 허용 오차는 0.5°다.
3. 기존 `TankGun`의 `OpenEmpty → Insert → Close → Fire → Recovering` 경로를 사용한다. 초기 약실이 열려 있으면 `Insert`부터 시작한다.
4. 발사 전 `TankBallistics.Predict`로 포탄 구체 경로를 검사한다. 자기 Collider를 제외한 첫 충돌 대상이 지정 표적에 속할 때만 발사한다. 기본 검사 주기는 0.1초다.
5. 실제 포탄 생성·충돌·피해는 `TankGun`·`TankProjectile`·`TankHealth`가 처리한다. AI가 표적 HP를 직접 깎지 않는다.

적 프리팹의 탄도 예측 자동 화면 갱신은 꺼 두었다. 게스트가 AI용 탄도 예측을 반복 실행하지 않는다.

## HP와 파괴 시 행동 중단

기본 HP는 100, 기본 포탄 피해는 25다. 네 번 명중하면 `100 → 75 → 50 → 25 → 0`이 된다.

- `TankHealth`는 유한한 양수 피해만 받으며 HP를 0 아래로 내리지 않는다. 비활성 Health와 이미 파괴된 대상은 추가 피해·피격·파괴 횟수 증가를 거부한다. 잘못된 초기 MaxHP는 100으로 보정한다.
- NetworkObject가 있는 전차는 Spawn 완료, 실행 중인 서버 Runner, StateAuthority를 확인한 뒤 HP를 변경한다. NetworkObject 없는 기존 로컬 표적은 로컬 피해 처리를 유지한다.
- HP·피격 기록 확정 후 `Died`를 한 번 호출한다. `TankAI`가 구독하여 다음 AI 틱을 기다리지 않고 `StopActions()`를 실행한다. 비활성화 시 구독을 해제한다.
- 자기 전차가 파괴되면 이동·공격을 `Idle`로 정리하고 새 명령을 거부한다. `TankGun`도 AI 요청과 장전·발사·회복 처리를 중단하며 `CanFire`는 false가 된다.
- 표적이 먼저 파괴되면 공격자는 `TargetDown`에서 멈춘다.
- 파괴 시 수평 이동·회전을 멈추고 중력에 의한 낙하는 유지한다. 차체·Collider는 잔해로 남고 렌더러가 어두워진다.
- 이미 발사된 포탄은 계속 날아가며 피해를 줄 수 있다. 파괴 직후 마지막 명중이 생겨도 새 발사라고 판단하지 말고 `ShotCount` 증가 여부를 확인한다. 종료된 포탄은 피해를 다시 처리하지 않는다.

HP 값·파괴 색상의 게스트 공유는 별도 동기화 작업이다. 시험 패널에도 HP는 **호스트 화면에만** 적·표적 값을 표시한다.

## TankTest 시험 구성과 진단

씬 루트 **Enemy AI Network Test**의 `TankAINetworkTest`는 기존 `SessionJoinInit`을 명시적으로 참조하는 Scene NetworkObject다. Runner와 다른 루트이므로 DontDestroyOnLoad로 함께 이동하지 않는다.

UI 명령은 호스트에서 접수해 다음 `FixedUpdateNetwork`에서 실행한다. 적·표적 참조와 시험 상태를 복제하므로 늦게 접속한 클라이언트도 같은 대상을 식별할 수 있다. 적 파괴·세션 준비 해제 시 예약 명령과 순찰을 중단하고, 생성 실패 시 부분 생성 대상도 정리한다.

고정 표적 `TankAINetworkTestTarget.prefab`은 기존 `TankTarget`을 바탕으로 네트워크 생성·Transform 공유를 추가했다. 초기화 시 `TankProjectile.SourceGun`으로 해당 시험 적의 포탄만 정리한다. 플레이어와 다른 오브젝트·포탄은 유지한다.

기존 은신용 Sherman과 플레이어 배치는 유지하고 제어 루트·생성 위치·순찰 표시·관찰 카메라를 추가했다. 관찰 화면은 켜져 있을 때 전용 RenderTexture로 렌더링하며 AudioListener를 추가하지 않았다.

### 위치와 속도 설정

| 항목 | 월드 좌표 |
| --- | --- |
| 제어 루트 | `(41, 0, -41)` |
| 적 생성 | `(43, 0.15, -35)` |
| 순찰 1~4, XZ 기준 | `(43, -35) → (55, -35) → (55, -23) → (43, -23)` |
| 고정 표적 생성 | `(47, 0, -13)` |

순찰은 한 변 12m다. 제어 루트 아래 `AI Spawn Point`, `Patrol Point 1~4`, `AI Target Spawn Point` Transform으로 위치를 바꾼다.

`Fast Test Movement`가 켜져 있으면 생성한 시험 적에만 이동 속도 6m/s, 이동 가속·감속 8·10, 회전 속도 120°/s, 회전 가속·감속 360을 적용한다. 원본 프리팹과 개별 시험 씬의 설정은 유지한다. 옵션을 끄면 프리팹 값을 사용한다.

순찰 전환은 실제 차체와 현재 목표 간 XZ 거리 1m를 기준으로 한다. 반경에 들어오면 `StopMove()` 후 0.1초 대기하고 자체 경로 인덱스로 다음 지점을 선택한다. 일반 `Arrived`의 엄격한 속도 기준만 기다리지 않는다. 네 지점을 돌아 첫 지점에 다시 도착하면 완주 횟수가 증가한다.

### 표시 값과 정체 경고

패널은 시험 상태·지점·완주 횟수·적 ID·위치·포탑/포신 각도·발사 수를 표시한다. 호스트에는 목표 거리, 이동·회전의 명령값과 실제 속도, AI·구동 갱신 횟수, Kinematic 여부도 표시한다.

**갱신 횟수는 코드 실행 횟수다.** 이전의 ‘물리 틱’ 표기도 같은 뜻이며, 이동 거리나 충돌 횟수가 아니다. 방향 차이가 크면 제자리 회전하므로 수평 속도가 0이어도 회전이 진행 중이면 정상일 수 있다.

3초마다 위치와 방향을 확인한다. 10cm 이상 이동하거나 5° 이상 회전하면 진행으로 본다. 둘 다 바뀌지 않으면 다음 원인을 구분해 경고한다.

| 경고 | 확인할 부분 |
| --- | --- |
| AI 판단 갱신 중단 | `TankAI`의 호스트·활성 상태와 갱신 횟수 |
| 차체 구동 갱신 중단 | `TankMotor` 권한·활성 상태와 물리 갱신 |
| 이동 중 구동 입력 없음 | AI 입력과 모터 입력 전달 |
| 구동 명령은 있으나 차체 정지 | 목표·적용·실제 속도, Rigidbody 제약과 접촉 상태 |

움직임이 회복되면 다음 확인 시 경고를 해제한다. 정체 경고만으로 장애물 충돌을 확정하지 않는다. 이동 요청 거부 시에는 `Rigidbody is kinematic` 등 실제 거부 사유를 표시한다.

목표 전환은 `[AI PATROL]`, 정체 발생은 `[AI PATROL STALLED]` 로그로 기록한다. 정체 로그에는 목표 방향 차이, AI 좌우 입력, 모터 입력, 목표·적용·실제 속도, AI·구동 갱신 횟수, Kinematic·Rigidbody 제약이 포함된다. 같은 경고를 매 프레임 출력하지 않는다.

## 기능별 개별 시험 씬

다음 씬은 로컬 Fusion Single 세션을 만드는 개발용 시험이다. 3인 동기화 확인은 TankTest에서 별도로 진행한다. 실행 전에 Play를 끄고 원하는 씬을 열어 Hierarchy 상단의 씬 이름을 확인한다.

| 씬 경로: `Assets/TankPrototype/Scenes/` | 용도 | 선택할 조작 오브젝트 |
| --- | --- | --- |
| `TankMoveTest.unity` | 목적지 이동·정지 | Tank Move Demo |
| `TankAttackTest.unity` | 지정 표적 조준·공격 | Tank Attack Demo |
| `TankAIIntegrationTest.unity` | 이동 → 정지 → 공격 → HP·파괴 중단 | Tank AI Integration Demo |

Demo와 NetworkRunner는 서로 다른 루트다. Runner는 실행 중 DontDestroyOnLoad로 이동할 수 있고 조작용 Demo는 원래 씬에 남는다. 예전 구성으로 실행 중이면 Play를 종료하고 현재 씬을 다시 연다.

### 이동만 확인하기

1. TankMoveTest에서 Play를 누르면 적 한 대가 Spawn Point에서 Destination으로 이동한다. 기본 목적지는 `(0, 0.03, 8)`이다.
2. 감속·정지 후 Console의 `[AI MOVE] Arrived and stopped.`를 확인한다.
3. Play 중 Destination을 옮기고 Tank Move Demo의 `TankMoveDemo` 컴포넌트 메뉴에서 **Move To Goal**을 실행하면 새 목적지로 이동한다.
4. **Stop Movement**로 이동 취소를 확인한다.

Destination을 옮기는 것만으로 명령이 바뀌지는 않는다. Move To Goal 실행 시 위치를 목적지로 복사한다.

### 공격만 확인하기

1. TankAttackTest에서 Play를 누르면 적이 Attack Target을 조준·장전·공격한다.
2. Hierarchy의 **Tank Attack Demo**를 선택해 Inspector의 상태·약실·실제 발사 수·표적 HP를 본다.
3. 약 10초 관찰하며 표적 HP가 `100 → 75 → 50 → 25 → 0`으로 감소하고, `TargetDown` 이후 추가 발사가 멈추는지 확인한다.
4. **공격 중지 (Stop Attack)**로 취소하고 **지정 표적 공격 (Attack Target)**으로 살아 있는 표적을 재지정한다. 파괴된 표적은 Play 재시작으로 초기화한다.

성공 기준은 발사 로그뿐 아니라 실제 명중 후 HP 감소다. Console의 `Tank fire: Fired #…`, `HP … -> …`, `[AI ATTACK] TargetDown`도 함께 확인한다.

표적은 기존 TankTarget을 바탕으로 구성했다. 자식 Aim Point의 위치 `(0, 1.3, -0.85)`로 피격 가능한 포탑 부분을 겨냥한다.

| 추가 시험 | 조작 | 기대 결과 |
| --- | --- | --- |
| 위치 변경 | Play 중 Attack Target 루트 이동. Aim Point는 표적 안에 유지 | 현재 위치 재조준. 이동 속도를 예측하는 선행 조준은 없음 |
| 가림 | 예: 위치 `(3, 2, 7)`, 크기 `(4, 4, 1)`의 Collider 있는 Cube 배치 | `Blocked / Shot path obstructed`; 벽 제거 후 재개 |
| 사거리 초과 | 표적을 `(0, 0, 100)`으로 이동 | `Blocked / Target outside ballistic range` |
| 표적 비활성화 | Attack Target 비활성화 | `Idle / Target unavailable`; 다시 켠 뒤 공격 버튼으로 재지정 |

### 이동·공격·자기 파괴 통합 확인

TankAIIntegrationTest에서 Play를 누르면 이동 → 도착·정지 → 지정 표적 조준·장전·공격을 자동 수행한다. **Tank AI Integration Demo**의 `TankAttackDemo` Inspector에서 자신의 HP와 표적 HP를 구분한다.

| 항목 | 기대 결과 |
| --- | --- |
| 이동 상태 | `Moving → Arrived`; 공격 시작 시 이동 명령은 `Idle` |
| 공격 상태 | 표적 HP 0에서 `TargetDown` |
| 실제 발사 수 | 요청 수가 아닌 실제 포탄 생성 성공 횟수 |
| 적 전차 자신의 HP | 시험 피해를 주기 전에는 100 |
| 공격받는 표적 HP | 실제 명중으로 감소 |
| 적 전차 파괴 횟수 | 자기 파괴 후 1 유지 |
| 파괴 후 중단 검사 | `PASS: stopped; new commands rejected` |

| 시험 | 조작과 확인 |
| --- | --- |
| 일반 피해 | **적 전차 HP -25 (시험용)**. 자신의 HP만 25 감소하고 생존 중 행동 유지 |
| 이동 중 파괴 | Play 재시작 후 이동 중 **적 전차 파괴 (시험용)**. 즉시 정지하고 도착 후 공격 예약도 취소 |
| 공격 중 파괴 | 조준·장전·발사 중 **적 전차 파괴 (시험용)**. 입력·예약 요청 제거, 새 장전·발사·회복 중단 |
| 파괴 후 명령 | 이동·레버·조준·공격·발사 요청이 거부되어 PASS 표시 |

HP 시험 버튼은 **포탄 충돌 없이 직접 HP 함수를 호출**한다. Console에도 시험 피해라고 표시한다. 실제 명중 시험과 구분한다.

**이동 후 공격**, **지정 표적 공격**으로 살아 있는 전차에 재명령할 수 있다. **전체 중지**는 이동과 공격 예약을 함께 취소한다. 전체 상태 초기화는 Play를 다시 시작한다.

## 네트워크 담당자 확인 순서

세 명이 같은 빌드와 TankTest 세션을 사용한다. 호스트만 명령하고 각 화면에서 같은 적 ID·동작을 확인한다.

| 순서 | 호스트 조작 | 각 화면에서 확인 |
| --- | --- | --- |
| 1 | 세 명 접속 후 적 생성 | 적·표적이 하나씩 보이고 적 ID가 동일함 |
| 2 | 사각 순찰 두 바퀴 이상 | 이동·회전·코너 정지가 전달되고 원격 AI가 별도로 실행되지 않음 |
| 3 | 이동 중 및 코너 대기 중 전체 정지 | 모든 화면에서 정지하고 뒤늦게 재출발하지 않음 |
| 4 | 지정 표적 공격 | 포탑·포신 방향, 포탄, 발사 수 전달. 호스트에서 표적 HP 감소 |
| 5 | 포탄 비행 중 초기화 | 새 적·표적으로 교체되고 이전 시험 포탄이 새 표적을 때리지 않음 |
| 6 | 순찰 진행 중 나머지 클라이언트 접속 | 기존 적을 중복 생성하지 않고 같은 진행 상태 관찰 |

전송과 보간 때문에 매 프레임 위치 수치가 완전히 같을 필요는 없다. 같은 경로로 움직이고 정지 후 위치가 수렴하는지 확인한다. 현재 클라이언트 비교 범위는 생성·제거, 차체·조준 회전, 포탄·발사 수, 정지 결과다. HP·파괴 색상 공유는 추가 연결 후 확인한다.

## 검증 결과와 남은 작업

런타임·Editor C# 컴파일과 Fusion ILPostProcessor를 통한 코드 생성을 검사했다. 런타임 컴파일에는 기존 경고 2건이 남아 있다. 마지막 모터 수정 후 런타임 컴파일·코드 생성·회귀 검사를 통과했다.

최신 로직 검사는 `Builds/TankAINetworkTest`에서 실제 제어기·AI·모터·조준·무기·HP·탄도 계산 소스를 함께 실행한다. 패널 17개, 공격 10개, HP·통합 9개, 이동 16개로 총 52개 검사 그룹을 통과했다.

주요 검사는 다음을 포함한다.

- 네 지점의 정확한 순서와 두 바퀴 순찰, 코너 대기 중 취소, 잘못된 도착 플래그, 시험 대상 초기화·부분 생성 실패·세션 준비 해제 정리.
- 기록된 반대 방향 잔여 회전에서의 출발, 좌우 회전·전후진, 큰 속도에서의 제동, 다른 AI·물리 갱신 주기, 예열 후 이동 루프의 관리 메모리 할당.

**로직 검사는 엔진·Fusion 서비스와 충돌을 대체 객체로 실행했다.** 시험 포탄의 피해를 Health에 전달하는 방식으로 명중을 모형화했다. 네이티브 PhysX 접촉이나 실제 Fusion 통신을 통과했다는 뜻은 아니다. 실제 TankTest의 지형 접촉·패널 배치·최종 모터 동작과 3인 접속·늦은 접속은 별도로 확인해야 한다.
