내부·플레이어 구성 정리 — 2026-10-29

환경: Unity 6000.6.3f1, Input System 1.20.0, URP 17.6.0.
대상 씬: Assets/Scenes/tankroom.unity.

저장한 구성
- TankInterior 아래 Room / Devices / Seats / DebugCameras로 기존 내부 오브젝트를 묶었다.
- 기존 벽·장치·좌석 등 19개 오브젝트의 월드 위치·회전·크기를 유지했다.
- pre-seat-1/2/3에 DriverAnchor / GunnerAnchor / CommanderAnchor를 추가했다.
- 원본 Polyperfect 프리팹은 수정하지 않고 몸 모델을 재사용한 CrewPlayer.prefab을 저장했다.
- 플레이어의 기존 보행·점프·전투·리스폰·자체 카메라·커서 스크립트와 이동 충돌체를 제거했다.
- 실내 카메라와 AudioListener 각 1개를 사용한다. 기존 내부 카메라는 개발용으로 보존하고 출력을 껐다.
- CrewLook은 마우스 시선, 클릭 시 커서 잠금, Esc·포커스 상실·비활성 시 커서 복귀를 담당한다.
- 자기 몸 모델은 1인칭 출력 중 그림자만 표시하며, 해당 시야나 컴포넌트가 꺼지면 원래 표시로 복원한다.
- 좌석 이동·역할 변경·장치 상호작용·전차 제어 연결은 다음 단계다.
- 네트워크 소스, 외부 전차 씬, 공급사 원본 에셋은 변경하지 않았다.

실제로 확인한 사항
- 새 스크립트와 임시 검증 도구의 Unity 컴파일 성공.
- 저장된 플레이어 루트는 Transform과 CrewLook만 보유한다.
- 남은 MonoBehaviour는 CrewLook과 URP 카메라 데이터뿐이다.
- Collider 0개, 누락 스크립트 0개, 출력 카메라 1개, AudioListener 1개.
- Play Mode의 9개 초기 검사 통과: 실행 여부, 불필요한 동작 스크립트 없음,
  이동 충돌체 없음, Rigidbody 없음, 카메라 부모 유지, 카메라·리스너 단일 출력,
  자기 몸의 1인칭 가림, Animator root motion 비활성.
- interior-play.png는 이 Play Mode 실행의 실제 Game 화면이다.

검증 미완료 / 수동 확인
- 가상 입력으로 클릭 후 커서 잠금을 확인하는 10번째 검사에서 조건이 충족되지 않아 중단됐다.
  실제 클릭 처리와 에디터 입력·포커스 조건 중 어느 쪽이 원인인지는 확정하지 않았다.
- 이후 마우스 회전, 상하 제한, Esc 해제·재진입, 보행·점프 키 차단,
  비활성 시 복원과 관리 메모리 할당 검사는 실행되지 않았다. 통과로 계산하지 않는다.
- 따라서 실제 사용자 입력 동작과 GC 수치는 아직 검증 완료가 아니다.
- 사용자의 컴퓨터 사용을 방해하지 않도록 직접 화면·마우스 조작 검증을 중지했다.
- Play Mode를 종료했고, Assets 안의 임시 에디터 검증 도구는 제거했다.

직접 확인 방법
1. tankroom 씬에서 Play 후 Game 화면을 클릭한다.
2. 마우스로 시선이 움직이고 몸과 카메라 루트 위치는 고정되는지 확인한다.
3. Esc로 커서가 풀리고, 다시 클릭하면 시선 조작이 재개되는지 확인한다.
4. WASD·방향키·Space·Enter로 보행·점프·병사 전투·옛 커서 토글이 발생하지 않는지 확인한다.
5. Play를 종료한다. 1/2/3 좌석 이동은 아직 구현 대상이 아니다.

백업과 도구
작업 전 사용자 변경이 포함된 씬·메타·diff와 임시 도구는
프로젝트 내부 Builds/InteriorPlayer-2026-10-29/에 보관한다.
실제 씬·플레이어는 해당 도구 없이 동작한다.
