좌석 이동·역할 적용 — 2026-10-29

대상: Assets/Scenes/tankroom.unity, CrewPlayer.prefab.
Unity 6000.6.3f1. 시작 좌석은 조종수다.

조작
- Game 화면이 활성 상태일 때 상단 1: 조종수, 2: 포수, 3: 전차장.
- 숫자패드와 방향키에는 좌석 이동을 배정하지 않았다.
- 승인되면 기존 앵커의 월드 위치·회전을 적용하고, 플레이어 자신의 TankCrew 역할을 변경한다.
- 좌석에 들어갈 때 CrewLook의 상대 시선을 초기화해 해당 좌석의 전방을 바라본다.
- 같은 좌석을 다시 누르면 위치나 시선을 다시 적용하지 않는다.

구조
- 새 CrewSeats가 좌석 요청, 승인 결과 적용과 세 좌석 참조를 담당한다.
- TankCrew는 기존 역할·권한 규칙을 재사용하며 CrewPlayer에도 별도 인스턴스를 배치했다.
- 현재 내부 플레이어의 역할이며 외부 전차의 단일 테스트 역할을 요청마다 바꾸지 않는다.
- 프리팹에는 자기 컴포넌트 참조만 저장하고, 세 앵커 참조는 tankroom 씬 인스턴스에 저장했다.
- 기존 씬 배치·앵커와 공급사 에셋을 보존했다. 씬 변경은 세 앵커 참조 연결뿐이다.
- 네트워크 코드, 기존 외부 전차 입력·이동·사격 코드는 수정하지 않았다.
- 장치 사용·전차 제어·관측 카메라 연결은 다음 구현 단위다.

추후 승인 연결
- localSeats=true: 로컬 검증용 즉시 승인. 시작·재활성화 때 startSeat로 진입한다.
- 담당자가 외부 승인 경로를 연결할 때 localSeats=false로 설정한다.
- SeatRequested(role, requestId)에서 요청을 받고 ResolveSeat(requestId, approved)로 응답한다.
- RequestSeat의 true는 요청 접수이며 승인 성공을 의미하지 않는다.
- 승인 대기·거절 중에는 기존 위치·역할을 유지한다. 새 요청은 이전 대기를 대체한다.
- 오래되거나 중복된 응답, 비활성화 중의 응답은 적용하지 않는다.
- SeatApplied는 위치·역할·시선 적용 후 발생한다. 후속 장치·관측 정리의 연결 지점이다.
- 이 승인 연결점은 통신·신원 확인·좌석 점유·교대 승인·동기화를 구현한 것이 아니다.
- 외부 전차 입력과 이 플레이어를 연결할 때는 TankInput의 직접 숫자 역할 변경 경로도
  좌석 요청 경로와 중복되지 않도록 조정해야 한다. 현재 내부 씬에는 TankInput이 없다.

검증
- Unity 컴파일 성공.
- 실제 Play Mode에서 results.json의 25개 검사 전부 통과.
- 시작 좌석, 1/2/3 매핑, 위치·회전과 역할, 시선 초기화, 기존 역할별 권한 확인.
- 잘못된 역할, 동일 좌석, 비활성 앵커, 비활성 역할 소유자 거부 확인.
- 승인 대기, 거절, 오래된 승인, 중복 승인, 비활성화 후 응답 거부 확인.
- 카메라 계층 유지와 출력 카메라·AudioListener 단일 유지 확인.
- Editor에서 준비된 유휴 키 처리 함수를 10,000회 호출한 관리 할당은 0 bytes.
  이는 해당 입력 처리 함수의 격리 측정이며 전체 씬이나 Player 빌드의 GC 수치가 아니다.
- 숫자키 검사는 가상 Keyboard 상태를 Input System에 넣고 실제 ReadKeys 함수를 호출했다.
  사용자 컴퓨터 사용을 방해하지 않기 위해 창 포커스·OS 키 입력·마우스는 조작하지 않았다.
  실제 Game 화면의 물리 키보드 입력과 화면 포커스 조합은 별도 수동 확인 대상이다.
- 이전 단계의 마우스 커서 잠금·회전 검증은 이번 숫자 좌석 검사로 대체하지 않는다.
